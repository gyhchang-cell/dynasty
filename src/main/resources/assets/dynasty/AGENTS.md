2026-10-11 当前奇观批次：遵循用户最新《建模要求.txt》00、18、19 节，`geo/scenic`、`animations/scenic`、`textures/entity/scenic` 按真实 UV 面积制作 128/256px 原创像素图集及非人形专用骨架，不受下文历史 16px/四色肖像 UV 限制。青苍龙影、玄武负岳、金乌巡天均为无 AI、无碰撞的客户端远景，保持现有编号和服务端时序，不改 Boss 或 NPC。

2026-10-11 开局书图标例外：用户最新明确要求重绘 `textures/item/dynasty_manual.png` 为至少 32×32、优先 64×64，使用深靛蓝封皮、分层古铜金包角/装订、小玉扣、中心王朝玉牌/龙云徽记、纸页厚度与少量朱砂书签。该图标不再受下文历史 16×16、四色、2×2 最小色块和白底规则限制；运行时使用透明底 PNG，另附中性背景预览。仍坚持硬边像素与离散明暗，不做平滑插画，不改书内界面和发书逻辑。此例外仅适用于开局书。

2026-10-11 当前人类 NPC 批次例外：用户最新要求以 Human Companions、MCA Reborn、Wizardry、Iron's Spells 人物画面为自然皮肤参考，并指定新版《建模要求.txt》19.3 的按实际 UV 面积选择图集规则。本轮 `geo/npc` / `textures/entity/npc` 使用原创逐面像素图集，允许 128/256 图集、眼白与肤色/布料/皮革/木金属的有限色板；下文历史 16×16 四色肖像规定不再限制这一批 NPC。普通人类保留人物身份。其他并行目标不在本轮改造范围。

依据用户 2026-10-10 的直接要求及随后授权的夜间实际改造任务。适用于本目录内后续新增、重做的模型、动画、贴图。先实际重做最差三个，再逐批处理 Cod2 中不合格生物；不得覆盖他人的并行工作。

## 技术参考与兼容目标

- Blockbench：https://github.com/JannisX11/blockbench 。重点参考 Cuboid、像素 UV、骨骼父子关系、旋转支点、模型导入导出。
- GeckoLib：https://github.com/bernie-g/geckolib 。本项目使用 Minecraft Forge 1.20.1 / GeckoLib 4.8.4，优先参考 `1.20.1` 分支，不能直接套用最新主分支接口。
- Blockbench Plugins：https://github.com/JannisX11/blockbench-plugins 。重点参考 `plugins/geckolib` 的格式和导出实现；插件可用不代表已安装或已连接。
- 不再默认使用在线 AI 建模或贴图网站。后续如需改变制作工具，以用户新指示为准。

## 造型

- 用户2026-10-11补充的《建模要求.txt》继续适用：每个待改小Boss选1～2个相关参考，实际查看暮色森林、灾变的官方展示或可查看的模型资源，记录借鉴的比例、头部轮廓、关节、武器重量或像素材质；不能只读README便声称看过。可用官方来源为 https://github.com/TeamTwilight/twilightforest 和 https://www.curseforge.com/minecraft/mc-mods/lendercataclysm 。参考不可访问时如实记录，不复制对方模型、贴图、动画、音效、建筑资产或换名套用角色。
- “不是方块人”指避免Steve比例与直筒身体、完整直棍手臂/腿加肩甲披风的组合；仍保留方块、长方体和有棱角的大体块。成品需要清楚的大轮廓、适量的局部结构、统一像素贴图和有重量的动作，并与原版石砖、草地和建筑协调。
- 保持当前Forge/GeckoLib兼容版本；不为建模升级整个工具链。插件仅用于确有需要的导出、UV和动画辅助，不安装来源不明的脚本。

- 制作原创、Minecraft 风格、低精度且轮廓鲜明的模型。灾变、暮色森林只作为质量和视觉方向参考，不复制其模型、贴图或独特设计。
- 只用长方体、方块、平面和粗颗粒阶梯近似；不用球体、圆柱、光滑曲面、细斜面、密集碎细节或写实高模。
- 拒绝 Steve 换皮式方块人。人形具有胸、腰、骨盆分段，真实护甲厚度、独特头盔和职业剪影；侧面必须有胸背厚度及甲片层次。
- 妖兽和 Boss 按生物形态建立专用骨架，不套普通人形模板。主要体块紧凑、易读，避免无意义堆积方块。
- 制作前说明主要 Cuboid、粗略比例、骨骼层级及动画想法，再实现实际资源。

## 所有贴图的共同要求

- 每次制作贴图都遵守清晰像素分区、有限配色、大色块和硬边界。
- 用户随后明确要求每次贴图都按 16×16 逻辑像素、最多四种纯色（含白底）、至少一像素白色边距、色区至少 2×2 制作。该直接要求优先于此前只把这些条件限定于物品图标的解释。
- 不用模糊渐变、柔光、抗锯齿、噪点或高清细碎表面细节掩盖造型问题。
- 实体也交付实际 16×16 PNG：可用正面像素肖像中的纯色岛映射 Cuboid 面，保留白底留边且不把背景采到实体上。UV 像素对齐，避免越界、接缝错位和部件意外串色；放大图只用最近邻。

## 物品图标的额外要求

- Minecraft Java 像素物品图标，视觉上恰好 16×16 格；若生成放大图，必须保持伪 16×16 大方格效果，实际交付检查像素尺寸。
- 主体不能碰画布边缘，四边至少留 1 格空白；每个色彩区域至少 2×2 格。
- 整张图最多四种纯色；白底也是颜色预算的一部分。零渐变、零抗锯齿、零柔边，所有颜色交界为硬边。
- 用户指定的图标图稿使用纯白背景，非工具主体正面朝前，轮廓应准确对应物品。
- 未经用户新指示，不自行改成超过 16×16 的图集、增加第五种颜色、渐变或透明背景；实体 UV 的装配需求通过重复使用有效色岛解决。

## 动画与接入

- 交付可加载的 `<id>.geo.json`、`<id>.animation.json`、对应 PNG；需要时保留 `.bbmodel` 源文件。
- 核对现有 Java 渲染器、动画控制器、资源路径和代码引用骨骼；保持资源 ID、动画名和挂点兼容。
- 检查父子骨骼、pivot、左右方向、动作关键帧、循环接缝、武器握持点和游戏内缩放。资源 JSON 可解析不等于游戏效果正确。
- 不改其他开发者正在处理的战斗、任务、AI、伤害判定等逻辑。共享工作区先确认目标资源是否有人正在修改，不覆盖他人未提交成果。

## 改造及验收流程

- 开始三实体改造时，先读取并实际查看现有模型与贴图，按轮廓、结构、UV、动作质量挑选最差的三个；不能只按方块数量或文件大小排名。
- 每个重要模型检查：正面、45°、90°侧面、背面、纯黑剪影，并记录需要修正的问题。
- 实际修改项目资源，检查贴图分辨率、UV、骨骼引用及动画范围，再运行适当构建与游戏内加载、动作和握持验证。
- 预览图和建议不能替代实际资源、构建或游戏验证。未完成的验证要明确说明，不声称通过。

## 首轮已核对的技术事实

- `build.gradle` 当前依赖 `geckolib-forge-1.20.1:4.8.4`。
- `geo/npc/mo_jizi.geo.json` 使用 geometry 1.12.0、128×128 UV，已有 `root → pelvis → waist → chest` 分层；其动画使用 1.8.0 格式及 `animation.npc.*` 名称。不能假定全部旧模型都是未分段人形。
- Blockbench `js/formats/bedrock/bedrock.js` 导出时处理坐标和旋转符号、pivot、box/per-face UV；不能把编辑器坐标未经核对直接抄为运行时坐标。
- GeckoLib 1.20.1 的 `GeoModel` 分别提供模型、贴图和动画资源位置；缺失骨骼可能被忽略，因此必须额外核对动画引用，不能依靠没有报错判定成功。
- 官方插件仓库的 `plugins/geckolib/src/ts/codec.ts` 启用骨骼和动画编辑，提供 GeckoLib 格式相关配置；学习这些接口不等于本机 MCP 已连接。
