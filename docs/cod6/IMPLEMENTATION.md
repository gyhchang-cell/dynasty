## 存档与操作

- 募兵台合成：3 铜锭、5 木板、现有虎符；交易从玩家背包扣银币。军籍随玩家数据保存，多个虎符打开同一军籍。
- 虎符“阵图”先选兵，再点 1–9 号位置；已占位置交换，伤亡后保留缺口。阵型按钮不会自动重新分配士兵身份。
- 未加载的野外兵请求收阵后显示“收阵中”，再次加载时核对 UUID 后收回，不因为暂时找不到实体再生成一只。
- 关卡目前为每名主将的独立场次。退出、死亡、重启后的未完成战斗安全撤离，不发胜利奖励；无法确认的遗留部署记重伤，旧载体失效。不是中途断线后满血重开。
- 屋顶修复明确提示天然材质可能由玩家放置，必须玩家预览后确认；不会自动翻修旧矿庄或扫描世界。
- 网络协议升至 8，服务端和客户端需要同版本。

## 可重跑验证

```sh
python3 tools/art/make_local_repo.py
./gradlew -Dorg.gradle.java.home=/path/to/java17 build
./gradlew -I tools/cod6-test.init.gradle -Pcod6Run=my-run \
  -Dorg.gradle.java.home=/path/to/java17 -x downloadAssets runGameTestServer
node tools/art/cod6_drawn_bows.cjs
```

本环境使用已缓存依赖和代理初始化脚本；上述 `/path/to/java17` 需要替换为本机 Java 17。没有修改仓库中已有的 Mac Java 路径。

最终本轮 18 项必需 GameTest 全部通过，`build` 成功。对应执行摘要见 `TEST_RESULTS.txt`。包含真实 ServerPlayer 的胜利任务回执、首领掉落传回，以及实际士兵死亡后的败北/重伤验证；不等同于正常装备手打的战术胜率。

矿箱 100 seed 的最终库存统计：900/2700 槽非空，平均堆数 9.9411；每箱固定 7 个矿类槽和 2 个原始材料槽。矿台检查到 13572 个实心矿物格，并测试了四旋转、路径、旧箱钻石与 v4 标记保留。

普通 Overworld 噪声生成器中的三个有效庄园起点（不是平坦测试世界放置的截图，也不是指南针 UI 实测）：

| Seed | X | Z |
| --- | ---: | ---: |
| 42 | -11040 | 38768 |
| 2026 | -5136 | 9312 |
| -731985 | -64256 | -26080 |

上述是按区域距离顺序找到的有效样本，不保证是数学上的最近结构。大型建筑仍很稀疏，罗盘搜索距离不足会找不到；本轮没有偷偷提高全世界生成密度。

干净天子剑伤害测试走真实 `hurt` 事件管线、无饰品/强化，并设置正式终局受击门控。基线 60000 HP 四击剩 51688；本轮 90000 HP 四击剩 81688。没有复现用户所述“未加成几刀击杀”原始存档场景，也没有把此测试冒充玩家完整祭坛通关。可加 JVM 参数 `-Ddynasty.damageAudit=true` 记录输入、护甲后事件和每 tick 实际生命差，定位重复事件。

## 尚待实机验收 / 本次范围限制

本容器没有图形显示服务，不能声称以下项目已完成视觉验收：四象演出/法术遮挡、Boss 贴图与动作精修、不同光影模组、左右手及第三人称弓握持、12–18 个士兵同屏帧率。小 Boss 本轮复用既有贴图，未提交一套全新 UV/像素纹理；拂尘的分段丝尾手部模型尚未制作。

战场已有服务端胜负及数据测试，但正确阵容/错误阵容/替代阵容的实战耗时、多人合作同场、断电事务一致性、全六关战术难度与完整 FTB Quests 客户端联调未验收。当前不提供多人同一场共同结算，也未把所有旧矿庄自动升级；这些不能标为“九项全部终验通过”。

`/locate` 和 Explorers Compass 客户端跨三个真实新存档的对照仍待实机；当前证据为注册分组检查及正常地形下结构生成入口探测。旧屋顶清理命令限定巨型雕塑结构的局部屋顶，不是全部建筑的通用翻新工具。
