# 三位人形Boss V10

用户2026-10-12明确纠正九霄天将、东海龙王、龙帝为人形。本轮只替换这三个已有注册实体的美术资源与必要的尺寸/渲染绑定。前八只已认可的非人形Boss、镇渊帝君、伤害、冷却、掉落、任务和战斗源码保持；不将旧“默认非人形”规则套到这三只。

单位为1/16格。主体高度约4格，冠/兵器在待机下总体约4.5格，显著大于1.8格玩家；脚不是主体最大体块。三张原创256²逐面图集按照展开面积重绘，并非旧PNG放大。参考作者PNG只远程查看，没有复制进运行资源。

真实参考图和部位判断见 `references.json` 与 `index.html`。Human Companions的皮肤/衣甲分区用于天将；MCA衣袍与脸的对比用于龙帝；Wizardry冰系巫师的人脸/白须/衣袍用于龙王；Iron's Spells火焰法师的深袍与腰带关系用于材质主次。未将室内、宣传光影当作基础PNG。我的判断是本版在Boss体量、关节发力、甲袍厚度和武器方向方面已比参考中的普通人物更完整；整体审美不作客观排名。

## 返工与验证

第一轮发现大眼黑白标记与平板胸甲；第二轮纠正肩肘、膝盖、毛须/袍摆与长兵器朝向。第三轮原生日光检查发现腰段与胸甲之间的天空空隙，及6 tick挥击被2 tick过渡吞掉前半段；增加已有腰段连接，三只的攻击/受击/死亡视觉过渡改为0。最终轮补尖头、扩大攻击取景，避免龙王刃部出画。旧轮次原生证据归档于本地 `build/boss-human-v10-history`，哈希摘要保留在 `iteration-history.json`；交付画廊只引用最终轮次。

实际链路仍是 DynastyClientEvents → BossCuboidRenderer → 同ID的 boss_cuboid geo/animation/PNG。保留真实装备 grip 图层；主手有实际装备时，仅这三只隐藏自带美术兵器，避免双持重叠。三只移除旧物种缩放，真实大小直接由模型单位决定。雷纹仅移动已有绘制位置，没有引入粒子或新技能。

`root→body→pelvis→waist→chest→neck/head`，髋→膝→小腿→脚、肩→肘→前臂→手/grip分别转动。六段动画保留原名称、时长和循环标记；原0.3秒攻击在中段有前送姿态，不改服务器伤害时序。完整walk包含摆髋、回收膝与对侧手臂；不是旧龙/器物动画换壳。逐帧最低面接地补偿避免穿地。

- 离线检查：UV整数标尺、岛不重叠/越界、全部六面、PNG声明一致；18段动作321点/段、有限坐标、骨骼引用、循环首尾、接地。已认可八只/锤链27个资源与基线字节一致，战斗源码一致。重复导出9个运行资产字节一致。
- 构建：隔离分支Forge1.20.1 / GeckoLib4.8.4构建通过；QA另编译，发布JAR不包含QA类。主目录另行构建因其他并行蓝图源码的10处类型错误失败，未修改这些源码。本次JAR是隔离美术分支构建，不包含主目录全部未提交改动；详见 `build-report.json`。
- 原生：三只各10状态，普通日光、无额外资源包/光影、玩家视高1.62m、真实玩家与草地/石砖参照。通过生产移动Controller、swing、hurt、death；实际geo/animation/PNG与冻结JAR的哈希相同。攻击出击截图等待真实前送姿态，不能单凭服务器包年龄命名。结果见最终 `native/human-v10-final/PASS.txt`。
- 实机边界：移动由测试夹具驱动，不证明自然寻路；“contact”是视觉峰值，不证明命中判定。cast是完整资源预览，生产控制器尚无服务器施法状态绑定，不能宣称落雷/龙息/龙焰与动作已同步。自然战斗、复杂地形、联机、真实装备持握仍需验证。

受击框同步至人形躯干，不给纯装饰另建服务器实体。Minecraft默认近战Goal的接近/触及阈值会受到实体宽度影响，因此旧巨龙/宽钟体的宽度缩小可能间接改变近战触及；没有改显式攻击距离、伤害或冷却。需要自然战斗验证。

测试只使用静音、隐藏的独立进程和一次性世界；没有调整系统音量/亮度、没有关闭或修改用户愚者存档。旧生成器的所有权检查会拒绝覆盖新版资源。

## 可重复生成

在仓库根目录，用Pillow/NumPy可用的Python运行 `tools/art/boss-human-v10/create.py`、`export_bbmodel.py`、`validate.py`、`review.py`、`gallery.py`。`export-owner.json`阻止覆盖手工或其他开发者的修改。可编辑bbmodel包含实际UV、PNG与全部动画。软件图、原色图、游戏截图分别标注，不互相冒充。
