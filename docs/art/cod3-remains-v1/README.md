# cod3 忠魂青铜像与死亡遗留物匣

本批实现任务清单中「忠魂解甲」的永久遗留物，以及 `StatueBlock` 的工程接入。十五 NPC 沿用上一批已验收资源；不改其他开发者的 Boss 招式、AI、任务、伤害与地下城逻辑。只扩展 cod3 已有死亡奖励容器的落点。

## 实际资源与结构

`dynasty:rebel_general_statue` 是静态、原创 Cuboid 方块，宽 14/16 格、高 24/16 格。下半块保存唯一的 54 槽库存及原 Boss UUID；上下半块的朝向和有无武器保存于原版 BlockState。上半块没有第二份库存。胸、腰、骨盆独立；厚肩甲、阶梯头盔、低落地膝、前抬膝、向后伸出的胫部和三段破披风形成跪姿。刀剑的刀刃插地，柄与手套相交。武器移出库存后，两个半块同步切到空手模型，手套和甲片保持原位。

`dynasty:lootable_remains` 从原版木桶改为漆木铜扣遗留物匣。保留原有 54 槽领取、保存、禁止投入和破坏掉落行为，满一格的箱体不改变原有碰撞外廓。两种资源使用 Minecraft 原生方块 JSON；静态方块不额外注册 GeckoLib 实体或假的 idle 动画。Blockbench 源文件保留未拆半块的完整体块和命名分组，运行时模型则准确拆成两个相邻方块。

原始体块、比例、分组见 [authoring.json](authoring.json)。所有几何只用轴对齐长方体和阶梯，未使用球、圆柱、平滑曲线或他人模组资产。建模前已说明体块及静态表现方案。

两张实际 PNG 都是 16×16，最多四种纯色（包含白底），四边留两像素白色空白，每个色区至少 2×2。正面像素图中的纯色岛重复映射到模型面，不采样白底；UV 为完整的两像素色岛，没有渐变、噪点、抗锯齿或自动拉伸 UV。五视角和像素图放大使用最近邻。

## 奖励与交互

叛将死亡结算只把已经捕获的掉落放入雕像，不新增装备奖励、不提高数量或改变词条。正常点击雕像任意半块，从原库存拔出一把原有的倚天剑；满背包则恢复原槽位。潜行点击打开遗留物库存，或者在剑已取出后正常打开，领取剩余掉落。服务器串行处理两名领取者，第二名不能取得同一把剑。

已有 `LootPlaced / XPAwarded / RewardGranted / Cleaned` 凭据继续防止重启重发。雕像放置完成后才移除旧 Boss；完成记录拒绝旧尸体再入场。放置仅检查原落点周围 5×5×4 的有限范围，只占用空气，不覆盖地形。两格高度都没有空间时，回退为原遗留物匣；连一格容器都放不下时，沿用原来的正常物品掉落兜底。

创造栏里的雕像是空的装饰品，放置不会产生剑。破坏任意半块会清理另一半，库存掉落一次；摆放装饰品不会保留原 Boss 奖励。

## 验证范围

构建采用独立输出和项目缓存，不读取其他聊天的编译目录。可选 QA 源集不进入发行 JAR。客户端使用复制固定的实际开发类路径，只打开 `build/` 下的临时平坦世界，不读取玩家存档。

本批首次短运行完成事务与五视角检查，发现跪姿和甲片闪面后离线修正，再做一次最终短运行。最终检查记录、资源与发行包字节对应关系见 [verification.json](verification.json)，正面、45°、90°侧面、背面、纯黑剪影见 [overview.png](overview.png)。原生世界、空手模型和重载后的图保存在 `evidence/`。

事务检查包含四朝向和单库存、带伤害/NBT 的原掉落恢复、满背包回退、两个服务器玩家对象争领、上半块点击、实际 BlockItem 放置、菜单取剩余物品、无回调取槽后的武器状态、上下半块破坏、受阻放置、死亡记录重启与重复恢复、旧尸体拒绝和低天花板旧记录兜底。两个领取者是同一真实集成服务器里的 FakePlayer；本批没有再启动第二台网络客户端，也不宣称新完成联机延迟验收。

只删除清单中完成的永久雕像/拔剑要求和专用雕像块实现选择。完整死亡过场动画、其他十九种死亡意象、NPC 支线和白鹿秘密继续保留。

## 本地工具

```sh
python3 tools/art/cod3/remains_resources.py
python3 tools/art/cod3/validate_remains.py
python3 tools/cod3/verify_assets.py
```

资源生成器仅重建这两种模型与贴图。`remains.init.gradle` 是按需使用的单客户端 QA，不会在普通构建中启动游戏。运行需独立 `--project-cache-dir` 和 `isolated-build.init.gradle`，用 `-Pcod3RemainsPrepare` 导出启动配置，固定类路径后再用 `run_remains_client.py` 启动。

技术参考仍为 [Blockbench](https://github.com/JannisX11/blockbench)、[GeckoLib](https://github.com/bernie-g/geckolib/tree/1.20.1) 和 [Blockbench Plugins](https://github.com/JannisX11/blockbench-plugins)。本批是原生方块模型，不改变项目 GeckoLib 4.8.4 依赖。
