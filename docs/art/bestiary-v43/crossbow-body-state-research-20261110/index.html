弩手：四阶段AI与真实双臂姿态

身体侧实现研究；不制作弩本体。同一 Human Companions 身体家族，新增参考验收信用为0。

  1. One shared wide Steve body. Arbalist role adds a four-phase attack-state machine, not another independently modeled creature.
  2. UNCHARGED waits for range/visibility condition, starts using the actual crossbow-holding hand, enters CHARGING and sets charging flag. Navigation may move while uncharged; charge movement uses half configured speed.
  3. CHARGING compares getTicksUsingItem against CrossbowItem.getChargeDuration. Normal duration25 ticks, Quick Charge modifies it. releaseUsingItem triggers item loading, then CHARGED delay20..39 ticks. Do not hardcode a 25-tick body clip as universal.
  4. Actual use hand is synced via LivingEntity flag bits; client initializes useItem from that hand and local remaining duration. The separate Arbalist IS_CHARGING_CROSSBOW flag is not read by CompanionRenderer.getArmPose.
  5. Renderer selects CROSSBOW_CHARGE when used hand/use ticks and UseAnim.CROSSBOW agree. AnimationUtils fixes holding arm yaw to +/-.8 and pitch-.97079635; support arm interpolates yaw .4 to .85 and pitch to -pi/2 as normalized use duration increases. This charging branch does not add head yaw/pitch.
  6. After successful load, CrossbowItem Charged NBT makes renderer select CROSSBOW_HOLD while not swinging. Hold branch follows head yaw/pitch with asymmetric holding/support arm offsets. It is distinct from the server CHARGED enum.
  7. CHARGED decrements randomized attackDelay; READY_TO_ATTACK fires only with visibility. AI calls performRangedAttack and clears charged tag on actual holding stack before returning UNCHARGED. This is state timing research only; no damage or projectile modification.
  8. PlayerModel copies animated arm transforms to sleeves. ItemInHandLayer consumes translateToHand plus third-person left/right context; shared body attachment ownership stays separate from weapon object authorship.
  9. canUse blocks eating, but canContinue can remain true if navigation is unfinished and target remains valid. Do not assume immediate cancellation merely from eating flag.
  10. Source stop clears target and seeTime but does not explicitly reset crossbowState/attackDelay. If using item, it calls stopUsingItem before CrossbowItem.setCharged(getUseItem(),false); native stopUsingItem empties getUseItem. Record this cleanup-order risk, do not assume held stack was cleared. No runtime failure asserted.
  11. AI entering CHARGED does not itself prove item loading succeeded: native release handler sets Charged only if load condition succeeds and Forge may intercept item stop. Body display should consume actual presentation state, not blindly mirror server enum.
