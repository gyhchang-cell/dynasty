goety-villager-body-family

simple body and garment layering

  • VillagerServantModel retains full-length 4x12x4 arms and legs; head is villager 8x10x8, body depth6. This is NOT a Steve six-cube donor.
  • The clothes part is hidden when chest OR leg slot holds ArmorItem. State-dependent clothing visibility is a pipeline decision, not extra joints.
  • ZombieVindicatorRenderer resolves neutral/hostile texture by isHostile and uses ItemInHandLayer. These two textures do not define two bodies.
  • ZombieVillagerServantModel instead consumes vanilla ZOMBIE_VILLAGER layers and calls vanilla setupAnim before zombie-arm posing. Do not silently substitute this geometry for VillagerServantModel.

For swindler/herb_picker: distinguish garment and actual arm inheritance; no new bodily segmentation is justified by this family.

Context only. Vanilla-derived variants and state skins are not separate semantic implementations.

goety-skeleton-villager

body versus worn shell; handedness

  • SkeletonVillager inherits VillagerServant body; narrow2x12x2 leg and arm cores are explicit, while arms also retain4x12x4 shell cubes.
  • prepareMobModel resets both arm poses, resolves main arm, distinguishes aggressive bow/crossbow hold/charge; setupAnim orders arm posing for two-handed actions.
  • translateToHand temporarily shifts the selected arm X by +/-1, applies its transform, then restores it. A hand interface need not be visible hand geometry.
  • Original64px atlas actually viewed: bone/light-gray body and dark garment regions; existing card is gray geometry plus separate atlas, not textured/game proof.

Preserve held-object interface independently of the bodily mesh; inspect shell visibility before comparing face budgets.

Existing family, zero new semantic credit; do not reset old accepted evidence.

iron-shared-casting-body

state-aware overlay instead of segmented limbs

  • AbstractSpellCastingMobModel gates custom head/leg motion while authored animation is active, unless explicit always-animate flags permit it.
  • Walk motion is resolved relative to facing and horizontal momentum, with reduced side displacement; this is not evidence to copy constants into Dynasty.
  • Arms get walking/bob only outside authored animation; drinking selects actual handedness; casting captures/restores arm snapshots.
  • CultistModel only overrides texture here. PriestModel selects archevoker geometry, armor-dependent texture and unhappy head movement. Two names alone do not establish two new skeleton implementations.

Do not add walk swing over a profession gesture or fake-injury loop; review controller ownership before editing a clip.

Shared base context, not separate credit for each subclass/skin.

  • Actual apothecarist64px atlas and existing four body-only source views inspected: coherent skin-colored regions, restrained dark belt/clothing and light fastening details. This is a reference atlas, never copied to Dynasty.
  • Inspected only three casting clips:25s charged hold, .1875s instant projectile recovery, .1875s finish. Holds, transient clips and loops must remain distinct; three clips are not three creatures.

For necessary humanoids: use restrained head-specific features and garment layers on simple limbs; separate item transform from arm body.

  1. actual client binding：AMEntityRegistry.RACCOON -> RenderRaccoon -> new ModelRaccoon; item layer installed explicitly. ClientProxy.java:136
  2. theft entry：Empty main hand and cooldown gate; approach villager; within1.7 requests standing, takes one actual offer stack, starts fleeTime60..119 and stops old navigation. EntityRaccoon.AIStealFromVillagers.canUse/tick
  3. escape and preemption：When route is done, asks DefaultRandomPos.getPosAway with raccoon.position() as the away reference and moves at1.3. This is not proof of moving away from the victim.   4. pose producer：Synced STANDING/BEGGING/WASHING feed0..5 progress, previous values saved for interpolation. Standing expires against maxStandTime; theft sets max15 but does not reset standingTime in that assignment, so exact15tick duration cannot be assumed. EntityRaccoon.tick/defineSynchedData
  5. body consumer：Reset pose then attack keyframes. Stand/beg/sit/wash blended into whole body/head/limbs; normal arm walking gated by standProgress<=0; legs continue gait. runProgress comes from limbSwingAmount, not a synced FLEE clip. ModelRaccoon.setupAnim/animate
  6. held-interface consumer：Actual MAINHAND stack follows root>body>arm_right when any raw beg/stand/wash progress>0, otherwise root>body>head. Includes baby scaling, local translations and rotations, GROUND display context. No item model is authored in this study. LayerRaccoonItem.render/translateToHand
  7. exit/recovery：Steal stop clears target/flee timer but not MAINHAND. Pose flags decay separately; washing/begging cleanup resets flags/navigation. An AI stop does not alone identify the visual recovery or empty the held stack. AIStealFromVillagers.stop; RaccoonAIWash.stop; RaccoonAIBeg.stop
