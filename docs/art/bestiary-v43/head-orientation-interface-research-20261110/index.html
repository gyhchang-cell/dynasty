  1. GeoEntityRenderer creates EntityModelData from body/head yaw difference and pitch, using negative netHeadYaw/headPitch in the data ticket. Merely producing this ticket does not rotate a named head bone.
  2. Entity instance ID is entity.getId(), not the generic GeoRenderer hashCode default. GeoModel retrieves manager by this ID, tracks current-frame timing and avoids repeat processing of the same rendered instance/frame. This is source behavior, not multi-entity runtime acceptance.
  3. GeoModel.handleAnimations performs processor setup/tick before calling setCustomAnimations. A local hook therefore runs after authored keyframe processing in the inspected path. Detailed current AnimationProcessor blending/transition behavior remains outside this bounded study.
  4. Current dependency CoreGeoModel.setCustomAnimations is default no-op: exact bundled4.8.4 class method Code consists of single opcode b1(return), max_stack0. This was read as classfile bytes with Python; no Java/JVM run or full decompilation. Earlier cached4.4.4 processor source is explicitly not substituted for4.8.4.
  5. ExpansionClient.Model does not override setCustomAnimations. For current two IDs the inspected model path therefore supplies no custom head-ticket-to-bone transform. Their numeric authored head tracks independently swing yaw between-3 and+3 degrees in idle/special/flee/evade; no Molang string expressions exist in either animation dictionary.
  6. This does not mean head geometry is frozen: authored head/neck/ancestor animation and whole-entity rotation still apply. It only distinguishes authored motion from an explicit local look-at offset. No screenshot or runtime failure claimed.
  7. Existing BossCuboidRenderer.Model supplies an explicit comparison: reads ENTITY_MODEL_DATA, exits for dying Mob, adds clamped data.netHeadYaw and headPitch (radians) to current head rotation. Limits .6yaw/.35pitch radians. This is a current project body implementation example, not a new creature reference or authority to transplant it into approved models.
  8. Existing WhiteDeerRenderer and BossForms hook context were checked only to distinguish resource-only and other-purpose hooks. Neither is counted as a new independent body study, and their approved resources are untouched.
  9. Any future look-at adaptation must preserve authored pose, verify data sign in the actual model coordinate basis, decide death/attack-state gating and account for additive reset. No clamp/sign/animation-timeline change is implemented under unmet applicable production gate.
