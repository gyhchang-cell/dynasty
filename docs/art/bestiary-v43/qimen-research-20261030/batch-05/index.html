暮色链锤：owner、存档与退出

TeamTwilight/twilightforest @ 80f4225c5c1525e7c9d18ddbfa35b8c22fd988f2 · Forge 47.1.0

逐条证据JSON

owner身份

Projectile优先返回未removed的cachedOwner，否则只在当前ServerLevel按UUID重查。没有health/isAlive/当前持握门禁，缓存分支也不比较level。ChainBlock普通构造与附加spawn约束Living owner，不扩大为任意外部改写的安全保证。

alive不是removed

LivingEntity.isAlive要求health>0，getOwner只检查removed。基础die可被Forge事件取消，基础tickDeath>=20时服务端移除。ServerPlayer.die覆写没有直接remove；Player基类/重生/断线未补全，不能承诺玩家死亡20tick必清理链锤。

真实命中与继续tick

ThrowableProjectile由轨迹结果经Forge impact取消检查进入onHit；Projectile向ENTITY/BLOCK覆写分派。随后仍处理阻力、重力和位置，没有通用命中即discard。ChainBlock先super.tick后自身owner/返程；未全文读ProjectileUtil交点筛选。

remove不等于卸载

discard/kill经虚调用remove；ChainBlock.remove先super，再仅按owner当前useItem类型stopUsingItem，不比原栈身份。区块processChunkUnload与客户端removeEntity直接setRemoved，不会仅因该调用进入ChainBlock.remove。tracking callback发离场事件；默认onRemovedFromWorld只清added标志，未穷尽外部监听。

owner查不到

ServerLevel.getEntity(UUID)读当前visibleEntityStorage；pending加载和追踪状态影响可见性。ChainBlock只要getOwner为null即discard，不区分尚未入索引、已卸载或不存在。缓存未removed时不查索引。真实加载先后及切维未实测。

存档恢复范围

Entity保存并恢复Pos/Motion/Rotation；Projectile追加Owner/LeftOwner/HasBeenShot，读Owner清cached。ChainBlock追加BlockAndChainStack并用ItemStack.of重建。不能说完全没有速度持久化；但自身bounce备份velX/Y/Z、isReturning、blocksSmashed、hitEntity、canSmashBlocks和HAND/FOIL未在其NBT覆写保存，不证明原持握栈引用或完整飞行快照恢复。

辅助链与multipart区分

已全文读BlockChainGoblin和TFPart。邻接怪物显式覆写isMultipartEntity/getParts；ChainBlock自己的partsArray只有构造赋值，类中无同样覆写或公开消费者，客户端逐链tick定位并由B4已读renderer绘制。Forge跟踪要求parent实际isMultipartEntity/getParts；私有数组和isPickable不能证明服务器碰撞注册。默认IForgeEntity/PartEntity及外部注入未读，不断言全局绝无multipart。

仍待验证

  • 准确Player.tickDeath、PlayerList重生/离线、跨维与外部监听顺序。
  • IForgeEntity/PartEntity默认multipart、ProjectileUtil筛选、EntityStorage磁盘编解码。
  • 原持握栈读档重绑定、左右惯用手与同步晚到、实机。
  • 本研究没有生物模型+PNG视觉参考信用。

IE railgun：玩家持握与实际绘制

BluSunrize/ImmersiveEngineering @ e63e4824800945eccf3684200a2c2270e2e1cdf2 · Forge 47.3.0

逐条证据JSON

实际资源绑定

Weapons.RAILGUN数据生成声明指向ie_obj、RailgunCallbacks、dynamic与translucent，并把transform输入烘成生成JSON。运行JSON实际指向models/item/railgun.obj.ie；不把原始transform输入的坐标或四元数直接等同最终display数值。

四手持display

实际生成JSON：FP左/右约Y=-84.375/+84.375度，scale约.125；TP左右scale约.1875，并各有不同旋转和位移。应保留原JSON完整变换与引擎镜像约定，不把角度单独照搬为握点。

真实玩家手臂

build.gradle声明mixins配置→client BipedModelMixin→HumanoidModel.setupAnim RETURN→IEBipedRotations。fancyItemHolding默认true但可禁用；仅Player分支遍历两手，right=(MAIN_HAND)==(mainArm==RIGHT)。Railgun设置持械侧arm.xRot=-.87266弧度约-50度；不是两臂通用支撑，也不检查isUsingItem或蓄能比例。

玩家与NPC区分

RailgunCallbacks.extractKey只scope/speed升级布尔；scope/speed/barrel_top控制模型组可见性。handlePerspective的额外变换明确只Fusilier且只TP；玩家依实际display和单独Biped注入，不能拿Fusilier庆祝姿态当玩家实现。

最终绘制消费者

IEOBJLoader读实际OBJ/callback→IEOBJModel.bake→General.resolve以stack/holder和shader生成Specific→applyTransform先display再handlePerspective→IEOBJItemRenderer绘可见groups与实际quads。ItemCallback默认无special-group动画/全亮；选定RailgunCallbacks没有充能时钟驱动机件动画。

真实材质和光照边界

IEOBJItemRenderer实际使用BLOCK_ATLAS、shader层色与输入light/overlay，按layer选translucent等RenderType。未查看railgun OBJ/MTL/PNG或shader具体注册，不能称外观研究、统一无乘色或完整UV验证。

粒子枪口不是弹道出生点

onUseTick shader近似front offset=.4375；发射效果=.75并映射usedHand/mainArm。普通RailgunShotEntity经IEProjectileEntity生于owner eyeY-.1。ammo properties允许getProjectile替换实体；未枚举所有弹药，不能宣称全部从同一枪口出生。

运行与姿态边界

只静态闭合玩家持械选定声明/消费者。原版第一人称ItemInHandRenderer、第三人称arm到item矩阵、其他模组动画注入顺序及真实fancy配置未验证；左右主手、双持及远端同步未启动游戏测试。

仍待验证

  • 运行时实际资源覆盖/配置；FP/TP vanilla完整arm到item矩阵及其他动画模组覆写。
  • 实际OBJ/MTL/PNG与shader资产未查看；不计生物模型+贴图参考。
  • 各ammo replacement实体、自定义shader和左右手/双持/远端游戏效果。
  • 全局独立语义去重与验收，1000门槛未满足，无生产授权转移。
