GrappleMod：一控制器内的局部解除与全组退出

固定提交 40080155cf1160b3ef4c6db9d47d01746925f9f1 · Minecraft1.20.1 / Forge47.1.0 / v13。选定正常链静态追踪完成，尚待独立去重复核，最多1项候选、已接受0。

  1. @Mod注册实体/物品；CommonSetup.init按明确PLAY_TO_SERVER/CLIENT注册消息。ClientSetup注册按键、manager和ClientEventHandlers。
  2. 客户端tick在未暂停且无GUI时检测输入边沿，主手优先选KeypressItem；发KeypressMessage(key,isDown)。服务器工作队列消费后重新按当前主手→副手取栈，不携带原始栈身份或hand。
  3. GrapplehookItem按doublehook和key决定单侧或throwBoth；先扣1耐久，破损则返回；createGrapplehookEntity把新钩登记进服务器玩家ID集合；左右活动引用另存Entity键映射。
  4. 钩碰方块serverAttach经规则检查后固定位置、附attached玩家ID；完整AttachMessage只发该玩家，AttachPos另发TRACKING_CHUNK。spawn额外数据携带发射者实体ID、rightHand、isDouble、custom。
  5. AttachMessage客户端解析折点/方向/custom，给钩clientAttach，再经实际proxy→manager.createControl。双钩且已有相同GrappleController时addHookEntity复用；否则创建并注册控制器。
  6. detachLeft/Right先清对应映射并removeServer。另一侧存在则发送DetachSingleHookMessage(id,hookid)，客户端只删该ID和该实体引用，不调用unattach；另一侧不存在则发整组GrappleDetachMessage。
  7. detachBoth清两映射、removeServer两钩、发整组消息。客户端unattach注销控制器，attached=false，对非AIR发GrappleEndMessage并切AIR；服务器消费后删除payload指定钩并再扫玩家集合，清attached和fallDistance。
  8. 真正绘制由注册的RenderGrapplehookEntity执行：拒绘死钩/死owner，以mainArm×rightHand选择侧，分别计算FP/TP手端；绘实际baked item和折点绳顶点。单钩被移除后该实体不再满足绘制门禁；不把consumer源码当实际画面验证。

不能忽略的缺口

  • 局部解除仍清总标记：detachLeft/Right即使另一钩仍活着也remove ServerControllerManager.attached中的玩家ID。客户端仍可保留另一钩，不能称服务器总状态完全一致；该集合所有其他用途未全局审计。 GrapplehookItem.java323–367
  • 丢弃右钩分支setter不一致：right映射分支调用setHookEntityLeft(player,null)而非Right；右实体被removeServer，但映射原值留下；getter因isAlive过滤不再返回它，不等同立刻删掉该map entry。未实机复现。 GrapplehookItem.java514–542
  • 输入释放门禁：GUI、暂停、看modifier block、手已无KeypressItem时选定链不发送该次释放。prevKeys更新范围不同；丢弃和死亡有独立路径，不能以普通松手链覆盖所有物品切换/断线情况。 ClientEventHandlers.java39–74,194–225；KeypressMessage.java53–83
  • 网络时序与控制器构造：AttachMessage即使未找到钩也继续createControl。构造器找不到钩时unattach依赖已注册控制器；新建尚未注册时不保证退出成功。实际spawn/attach先后和延迟表现未验证，不声称无缺失实体问题。 GrappleAttachMessage.java128–144；GrappleController.java59–106；ClientControllerManager.java300–370
  • 反向退出归属：ctx sender非空后，payload entityId/hookIDs交给manager，本段未验证与sender/owner相等。不推断真实服务器可利用性，也不将其作为可直接移植的安全范式。 GrappleEndMessage.java59–69；ServerControllerManager.java33–54
  • 一般移除不等于集合清理：removeServer只remove+shootingEntityID=0；不会自行清左右map/全部集合。整组结束和死亡另有清理。不可钩方块/命中实体等提前移除及断线/跨维/卸载是否充分清理未完整闭合。 GrapplehookEntity.java146–159；ServerControllerManager.java14–31；CommonEventHandlers.java55–80
  • 存档恢复未知：发射者通过自有临时Entity引用/ID和spawn附加数据；选定类未看到持久化这些状态或重建左右map/controller的自身NBT覆盖。基类/能力/外部事件完整存档链未读，不承诺重载可恢复或必然崩溃。 GrapplehookEntity.java59–149,534–544
  • 物理与资产范围：GrappleController的updatePlayerPos全文已读，内部SegmentHandler/Vec/Config辅助未全读；AIR其余实现、物品JSON/PNG未读。真实绳顶点消费者已追到，完整手持材质与实机效果未验证。 read_ranges及未读断点
