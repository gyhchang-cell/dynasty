# 悬闸狗头铡：本地实现，未实机验证

2026-10-18。对应Cod2“阴司枉死城”的铡刀落闸及追加机关 `guillotine_trap`。本批实现机关本体、运行资源和管理员调试通道；**不是整座枉死城完成，也未通过Java编译或实机验收**。

## 实际接入

- 注册受保护的 `dynasty:guillotine_trap`，复用现有 `DungeonMechanismBlockEntity`、房间SavedData和每两tick的核心调度。没有新增全世界扫描或自然刷怪。
- 天花板为锚点，刀刃宽2.75格、厚0.375格、高0.75格；固定导轨、上梁和连杆说明支撑关系。刀身两面均有耳、眉、眼、口鼻组成的狗头浮雕；它是器械，不是生物或人形模型。
- 4份真实方块模型、4份可编辑Blockbench源和四朝向方块状态已导出。Renderer从服务端相位绘制刀刃下落及抬升，扩大渲染包围盒覆盖完整运动范围。
- 默认时序为20tick预警、4tick下落/接触、16tick抬升。伤害在ACTIVE第2tick产生一次，未装加长预警改件时每40tick循环。伤害8点，作用范围为狭窄刀刃扫过的体积，不是整条走廊；不改地形、不推挤镜头，不生成实体刀片。
- 地面火线、中文提示及链条松闸声提示玩家离开落刀平面。转向同时旋转视觉和服务端判定。身体退出该平面即可避开这次攻击；真实玩家移动效果仍待实测。
- 离场或运动范围受阻时停驻收刀，再进入或清障后重新完整预警。核心卸载、时间跳变后也重新预警，不追赶遗漏伤害。房间完成后停用铡刀。长时间无人时仍沿用现有房间暂停逻辑。
- 新增 `ContactDelay` 存档字段默认0，旧机关保存数据兼容。现有八种机关的时序经修改前后源码解释对比保持一致。

管理员现有结构 `dynasty:dungeon_framework_probe` 的末段新增三格宽通道、承重墩和天花板横梁，锚点相对结构原点为 `(6,4,37)`，机关ID为 `guillotine_probe`，与原核心绑定。未来获准运行游戏时可用 `/place structure dynasty:dungeon_framework_probe` 放置，在附近用 `/dynasty dungeon trap test guillotine_probe` 调试。以上命令本批没有执行。原结构不自然生成，没有把调试结构加到玩家指南针或伪装成枉死城到访任务。新增方块名称与预警均有中文、英文条目。

## 贴图协作与参考边界

按用户指定，已联系原“回应问候”、现名“做贴图的”对话制作专用图集，明确要求它不运行Java或安装脚本。对方尝试三版，实际采样区内仍有色块柔化，未达到本次材质目标；原稿、提示和限制保存在 [texture](texture/TEXTURE_READY.json)，`ready=false`，没有进入运行资源。

最终模型直接引用Minecraft已有的铁砧、铁块、深色橡木和斑驳铜材质，未复制、缩放、量化或替换运行时PNG。`preview-materials.png`只是软件渲染时读取原版材质形成的本地采样图，不是运行贴图。Blockbench文件内嵌材质用于本地编辑。

本轮按照清单的悬挂铡刀、真实关键帧、预警和持久化要求制作。沉沙玄宫已有的100个建筑参考不冒充枉死城的100个参考；本轮没有宣称完成枉死城建筑研究或主体建筑。

## 检查结果与尚未完成

[10项Python检查](python-tests.log)通过：直接解析并解释生产Java中限定的时钟和运动函数，核对接触延迟、40tick周期、旧机关时序、暂停/时间跳变、四向判定和资源链；也包含10份相关Java源码的语法解析、模型UV和同向共面重叠检查。解释器保留时钟中Java整数除法语义，但不能验证Java类型、Forge API或游戏行为。

[八视图及动作阶段](model-review.png) 已实际查看，修正了木梁与铜箍的共面闪烁及狗头浮雕的宽高关系。视图来自导出的实际Cuboid和生产运动函数，是软件预览，不是游戏截图。

已准备3项原生回归源码，更新既有机关时钟测试以接受铡刀的延迟接触。Java/JVM/Gradle、构建、打包、客户端、服务端均未运行；没有修改存档、声音亮度或上传GitHub。
