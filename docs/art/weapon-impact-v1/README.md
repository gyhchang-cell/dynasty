# 七种武器：材质命中与三种闪屑时序

本轮补齐 cod4-3 的四种基础材质命中，以及青釭剑、镀金锏、倚天剑三种独立节奏。实际生产代码为 `cod3/WeaponImpactVisual.java`、`client/WeaponImpactRenderer.java` 和原 `Cod3VisualPacket` 的客户端分流；没有更改公共 `Cod3VfxRenderer`、武器伤害、任务、怪物 AI 或其他聊天的模型。

| ID | 实际几何与时序（tick） | 单实例峰值三角形 |
|---|---|---:|
| mu_mao | 木屑长方体，0 发散，受短时重力 | 48 |
| shi_ge | 灰石碎块，0 发散，受短时重力 | 36 |
| tong_dao | 铜色宽短交叉平面，0 发散 | 20 |
| tie_jian | 铁灰薄快交叉平面，0 发散 | 16 |
| qinggang_sword | 青色两次扇形，0/3 | 24 |
| gilded_mace | 金色轻点、重闪、余屑，0/2/6 | 28 |
| yitian_sword | 冰白三次交叉剑痕，0/2/4 | 16 |

几何仅用长方体和硬边平面；木石使用三种离散面色，闪屑每种单一有限色，无贴图噪点、柔光贴图或圆滑曲面。每种最多12 tick，实测所有顶点距命中点小于1.7格。侧向有交叉面，尺寸以真实世界格计，不改变物品模型或持握点。软件自查后加深铁剑/倚天剑，并加宽铁剑/青釭剑/倚天剑的细痕，改善浅背景下辨识度。透明度只有时间衰减，面内没有渐变。

服务器在原生 `LivingDamageEvent` LOWEST 观察实际正伤害，复用已有 `sourceWeapon` 来源过滤，并要求直接玩家近战；箭矢、间接法术、取消或零伤害、外部模组物品不能借用手持武器触发。独立持久字段每玩家每 tick 最多一次，未改原 combo/武器判定。仍用既有数据包字段、32格广播；客户端独立队列最多12条，去重、维度校验、过期/换世界清空，64格外不绘制，并恢复 GL 状态。七星刀、通用残影和其他 cue 继续原分流。

`ImpactCheck.java` 实际运行生产几何、时序与 FriendlyByteBuf 编解码，通过240420项检查，包括五种方向、四种种子、每1/8 tick取样、有限范围、非退化面、三个不同节奏、过期/NaN/巨大错误包拒绝。完整三角形和测量在 `actual-triangles.json`；`software-views.png` 包含正、45度、侧、背、黑剪影、灰色检查，`software-rhythms.png` 为三把名器实际时序。**这些是同尺度软件几何诊断，采用不透明面检查形状和颜色，不是游戏截图，也没有验证真实透明叠加或游戏光照。**

隔离无图形 Forge 服务器三项 GameTest 全部通过：七把真实注册物品调用原生 `Player.attack` 后经过 Forge 监听；拒绝无效来源且不追加伤害；同 tick 去重及真实玩家类的 NBT 写入/读回。参与者为 FakePlayer 与一次性测试牛，**不是真人、客户端画面或联机验收**。初次第三项错误使用不可序列化的 `Player.save`；测试修正为 `saveWithoutId` 后复验通过，没有为迁就测试改伤害逻辑。首次整仓构建撞到并行墨影刺客客户端编译错误；测试服临时只排除该无关客户端类，生产构建不排除。该开发者自行修复后重新读取冻结源并做最终整仓 build/reobfJar，结果见 `verification.json`。

构建、QA工作目录为 `build/maintenance/weapon-impact-v1/`；保留初次失败与最终日志、源哈希和并行刷新记录。冻结构建不覆盖共享整合包 Jar，也不推送 GitHub。用户愚者游戏/存档不关闭或修改，没有启动图形客户端、唤醒屏幕或改变声音和亮度。

**仍需实机**：原残影与新增闪屑同屏组合、浅/暗背景、第一/第三人称、透明面重叠、低帧率观感；32格真人双客户端广播/视距/多人重叠。原 cod4/cod6/建模要求均在 `prompt-before/` 先备份；这些要求尚缺完整实测证据，对应原提示词保持，不删除部分完成条目。
