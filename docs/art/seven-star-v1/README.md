# 七星刀：七次依序闪亮

修复cod4“七星连闪”的实现缺口：原成功命中走通用VFX21星雨；现在 `seven_star_saber` 发送同一视觉协议中的独立 `equipment_seven_star_hit`。第0、2、4、6、8、10、12 tick分别点亮一颗星，每颗3 tick硬边淡出，全部16 tick结束；最多同时亮两颗，不再用一团随机星雨表示连闪。

`cod3/SevenStarFlash.java`保存独立短时序、七点形态和原32格广播。`client/SevenStarFlashRenderer.java`沿世界垂直面绘制明确星形，并有交叉平面供侧向玩家观察；短连线串接星点。原服务端成功命中的伤害来源、弓箭过滤、同tick去重、combo、暴击和武器残影均保留，仅替换七星刀的一处命中表现分支；没有追加伤害、冷却、持续服务器任务、音效或相机变化。紫薇刀/诛星弓及其他星雨用途继续走原模板。

复用 `Cod3VisualPacket` 的既有字段，不增加消息类型/字段或更改协议。客户端仅消费精确的专用cue；其余全部转给原公共渲染器。专用队列最多8条、去重、校验维度与时长、过期或换世界清空；64格外不绘制。每次渲染恢复原GL状态。未修改其他聊天正在使用的 `Cod3VfxRenderer` 和奇观资源。

实际Java `SevenStarCheck`通过2575项：七次唯一顺序、生命周期边界、最多两星、10/15/30/60/144FPS时间采样仍可见所有七次、水平/竖直/零方向下坐标稳定、局部有限包围、真实FriendlyByteBuf编码/解码无丢字段和尾字节、普通星雨不被劫持、专用超长/NaN包拒绝。见 `timeline-codec.log`。这些是实际运行Java逻辑和协议测试，**不是客户端观感或真人联机验收**。

冻结5132源文件的最终离线build/reobfJar通过，Jar包含新类及最新五人资源，未打入检查程序。冻结Jar不覆盖其他开发者继续更新的共享整合包Jar。源哈希、包哈希及其他并行源的变动见 `verification.json`。
