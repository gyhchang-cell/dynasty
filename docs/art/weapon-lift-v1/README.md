# 环首刀、巨阙：真实抬升之后的尘土与弧光

本轮接入 cod4 `huan_shou_dao / juque_sword` 的实际上扬反馈。巨阙已有 `push(0,.4,0)` 和60tick减速II，环首刀使用原版受击击退；两者均不新增浮空、位移、伤害、硬直、音效或相机。没有按武器名字直接播放起飞。战斗类、流派战斗类和公共 `Cod3VfxRenderer` 与开始备份逐字节一致。

`cod3/WeaponLift.java` 捕获真实原生攻击前的武器、目标位置、速度和支撑地面。在同tick、同攻击者/目标、同一DamageSource对象的最终正伤害后创建短观察回执；间接/法术/合成/取消/零伤害拒绝。原版击退会在最终伤害事件之后才完成，故本轮不在 LivingDamageEvent 中凭瞬时速度猜起飞。服务器tick末首先要求真实正上扬速度增量至少0.18和有效顶上空间，再等目标实际升高至少0.02格才发送。四tick未移动即失效，已有空中上升不能代替新冲量。攻击者/目标死亡、移除、跨维度或异常位移均清理；候选与等待队列各最多32条，每玩家每确认tick最多一条。

支撑地面采用真实Collider射线和onGround状态，检测接触高度、实际地面MapColor；尘土只留在起跳接触点上方0.015格。不把无支撑空中攻击或液体当成有尘土地面。实体弧光跟随真实插值脚点，落地即停止，不运行另一条假弹道。8tick为视觉上限，不强制目标浮空0.4秒；实际落地由原版移动和重力完成。

制作前方案在 `plan.json`。五段折角交叉平面弧光，巨阙克制铜金、环首刀灰蓝；四个真实Cuboid小碎块使用实际地面色及两档硬明暗。自检将最初浅奶金/浅蓝调深，避免浅色背景读不清。源为原生POSITION_COLOR程序几何，不需要无用途PNG/geo/animation文件；可编辑源、动画时间和真实挂点都在生产函数。单实例最高68三角形、实测局部半径1.18格、尺度0.45–1.2，12客户端实例、32格广播、64格绘制距离。独立缓冲、现有GL状态恢复器；不结束共享BufferSource。`Cod3VisualPacket` 仅新增专用路由，字段和原编码不变。

实际生产Java `LiftCheck` 通过904326项几何/位置/状态/原FriendlyByteBuf检查，覆盖两武器、12方向、三尺度、地面/无支撑、每半tick、空中/落地输入：弧光随目标平移、尘土固定地面、碎块不沉入地面、生命周期、有限范围、非法cue拒绝。`actual-triangles.json` 来自当前生产函数。`software-views.png` 实际检查正面、45度、左右侧、背、灰色与纯黑；`software-timeline.png` 检查落地输入后不再绘制弧光。**输入姿势是明确受控的软件诊断，不是原生轨迹；这些图不是游戏截图，不能证明GL透明、真实光照或人体遮挡。**

隔离真实Forge无图形服务器九项通过：巨阙原生 `Player.attack`、原0.4冲量/减速II、真实升高后确认以及按原重力落地；环首刀原版击退确实升高；真实顶板半砖限制顶上空间；Forge取消原版击退；后续取消伤害不能借用既有巨阙push；其他剑和原已上升的目标拒绝；不同DamageSource不能偷回执；原生全抗击退与无支撑空中巨阙抬升；攻击者死亡后不保留延迟视觉归属。起跳射线验证实际石块顶面和MapColor。FakePlayer和一次性、无游走目标但保留真实原版移动/重力的Cow测试体均仅在隔离世界，不是真人、用户存档或客户端。第一轮NoAI夹具只有速度没有位移，正向测试失败；已更换正确夹具，失败日志保留，最终九项全过。
