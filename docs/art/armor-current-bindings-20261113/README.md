# D73：当前项目28件盔甲资源链核查

本轮完成项目自身的只读核查，未生成或覆盖新美术。范围为竹甲、织锦袍、布衣、皮甲、鲛绡、鸿蒙、朱砂符甲各四件，共28个ID、70个运行资源文件。要求全文、哈希和目标已随批保存。

## 已核实的实际内容

- 竹甲、织锦袍、朱砂符甲12件图标与v29获选原稿逐RGBA像素一致；鸿蒙4件与v25获选原稿一致。复核按历史裁剪坐标重建并加2px透明边距，仅在内存比较，未缩小、量化或改动运行文件。
- 上述16件使用 `dynasty:original_item`，直接读取原始PNG尺寸，独立纹理绘制；共享blocks图集的filter正好排除这16件，属于现有接入方式，不能误报成缺失图集引用。铁粒图集引用仅用于particle占位。
- 布衣、皮甲、鲛绡12件使用 `item/generated`，当前PNG与v15候选实际字节相同；它们已有历史重画，不能单凭年代较旧认定为“从未做过”或获准重做。
- 全部14张穿戴图集目前仍与v15候选PNG完全一致，均64×32。16件图标换过原稿不代表穿戴图同步重画过。历史v15清单中 `resource_pack_only_not_installed` 是当时状态；当前源码确实包含相同候选字节，但不能据此宣称用户正在运行的游戏已加载。
- 当前入口是 `Dynasty -> DynastyContent.register -> DynastyGear.ITEMS`。四槽构造器、七种材质名、Forge47.4.10默认消费者已逐项对应：护腿走layer_2，头盔/胸甲/靴子走layer_1。未在本次限定源码链中发现错材质名、错层或缺失图标路径。
- Dynasty皮甲同样是普通ArmorItem，不是原版可染色皮甲接口，不能凭“leather”名称要求overlay。额外圣光层只匹配 `xuantian_`，不作用于这28件。
- 当前 `src/generated/resources` 没有这70个同名资源；现存 `build/resources/main` 的70个字节都与源码一致；`modpack/resourcepacks` 内两份ZIP均没有同名覆盖。未读取用户实例，用户实际启用资源包、其他模组替换和已加载Jar优先级仍未知。以上不是新构建或实机验证。

## 纠正旧“头顶风险”措辞

从本地精确版本消费者的顶点与UV构造重新推导：普通中立姿态下，头部模型y_min=-8对应实际头顶，图集矩形是 `[8,0,16,8]`，枚举名却是Direction.DOWN；y_max=0对应头部下侧，矩形是 `[16,0,24,8]`，枚举名是Direction.UP。LivingEntityRenderer的 `scale(-1,-1,1)` 是该方向对应的重要上下文。

因此，右侧矩形为空不能直接证明头顶缺图。实际头顶矩形：竹甲/鸿蒙/朱砂64个非透明像素，织锦/布衣/皮甲/鲛绡52个；下侧矩形仅鸿蒙64个，其余为空。局部透明也不能单凭计数判定错误，可能属于开口设计。此处修正旧记录面名的解释，不修改历史冻结文件，也不据此补画贴图。精确测量见 `head-horizontal-face-correction.json`；仍需独立复核和实机接缝验收。
