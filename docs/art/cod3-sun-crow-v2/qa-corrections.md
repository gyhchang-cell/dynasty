# 实机返修记录

第一轮不是通过证据。前六组正常、全精度近景通过；140格远景为0像素，截图确认全雾。测试视距当时6区块（96格），测试点超出原版雾终点；第二轮将测试视距设为12区块，保持140格测试距离和像素门槛，不以降低门槛掩盖。

人工检查侧视还发现原有medium精简会丢弃厚度1的眼睛，使金乌侧面没有识别点。正式生成器及更新导出器已保留中距离头部全部细节，medium从45块改为47块，full仍48块，far仍23块。贴图未变。

第二轮：140格远景恢复可见，中距离眼睛已确认。雨天开关截图均未显示鸟，但旧像素谓词把绿色草地上的移动雨条误算为金乌（110696像素）。改为要求红分量大于绿分量6，符合乌金/古铜色并排除草地；用第二轮全部12组原图复算，十个应显示场景仍为7221～76865像素，夜/雨均0。第三轮保持同一显示/隐藏阈值复验，不更改正式资源。

继续人工比对两张振翅帧发现旧控制器adjustTick返回未取模的包年龄，超过80tick时总落在动画末尾，非零骨骼角度检查未能发现静止。修正为真实动画周期内的绝对包相位，并加入从正式animation.json独立插值、与实机翼骨角度比较的断言（含迟到观察者）。共同远景控制器同步受益，其他模型资源未修改。

核对本地GeckoLib4.8.4字节码及官方1.20.1 GeoObjectRenderer发现传null顶点buffer会将传入BufferSource替换成共享全局buffer；正式调用改为显式传自有BUFFERS.getBuffer(type)，确保自己的endBatch确实只提交本批远景。

第四轮17场景自动检查通过，真正的抬/压翼角分别约−0.453/+0.309弧度，与关键帧和包年龄一致。但人工联系表发现原far抽样每隔一根羽片会造成翼尖断开。最终far保留全部五根相接的主羽、仅去掉亮色末端薄片，从23改为27块，保持完整骨架及同一动画。此为实际资源修正，须再次原生验收。
