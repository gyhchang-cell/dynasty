# 独立接受汇总协议 v2

唯一写入者为本研究岗summarize.py。读取independent-reviews下全部JSON，原收据和proposal批次不改。

授权来自用户本对话明确分工：coordinator与Carson。receipt_validation.py固定每个role的文件命名空间、精确reviewer label和接受decision白名单。未知角色/相似字符串/错角色decision不接受。当前协调格式ACCEPT_ONE_RELATED_IMPLEMENTATION；Carson格式ACCEPT_ONE_RELATED_IMPLEMENTATION_WITH_EXPLICIT_LIMITS。后续变更标签或decision须明确核定后修改白名单，不能宽松startswith匹配。

必须对应已全文读提案的完整id、semantic_key和实际batch SHA256；Carson reviewed_batch同时要求精确路径。候选/未知id/信用非整数1或decision为reject/gap/candidate不计。source_checks必须按原链全部范围一一对应，不缺范围、不用重复范围充覆盖。协调旧格式的PASS也不作字节真值：每条独立重算source SHA256、Git blob header SHA1、原文件excerpt及SHA、固定URL，并核metadata实际repo/sha或commit、同commit完整tree与blob entry。Carson另外绑定的所有源值及metadata SHA也须逐项相同。额外DataGenerators整文件支持也复核全文及Git来源，信用0。

每个真实收据记录实际原字节receiptSHA；本次读取的receipt/batch/source/metadata/tree在发布前再读SHA确认不变；目录新增/删除收据导致本次停止发布，重新做文本核验。汇总保留per-reviewer原文件路径、SHA、来源复算证明、完整语义观察及限制，不能将表单PASS替代独立语义审阅。身份是用户授权的本地角色+命名空间+精确label校验，不宣称拥有远端身份签名或独立Git commit object认证。

跨reviewer同id且同semantic/batch的完整接受收据最多计1，所有review都保留。授权namespace的无效或非接受收据与有效接受同id时，自动hold0并列conflict；不同semantic/batch也不选一方；跨id重复semantic key同样hold0。纯语义文字意见的深层冲突仍需人审，本汇总不冒充自动重新研究或自动证明两个措辞等价。

receipt-validation.json列全部输入、失效原因和冲突。master、continuation与delivery-inspection共享aggregation_id，JSON以临时文件replace完整发布。receipt/批次本体不写。aggregation-counterexample-audit.json中的43个内存反例不写入收据目录，不是Minecraft测试或新增研究信用。
