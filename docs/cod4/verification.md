## 自动验证

`build` 与 cod4 专项 `runGameTestServer` 实际在 Forge 服务端执行；最终结果见 `test-results.txt`。

专项覆盖：30 实体实例化与存档、敌对分类、阴阳层数、雷印引爆、属性重复刷新与卸装、玩家间状态隔离、弩弹药消耗和存档、错误弹药与未完成蓄力、妆匣去重历史、致死保护及 `/kill`、喂食流民、合成伤害保护清理、弩成长武器身份、镇渊帝君控制免疫、互动奖励一次性、共享连击同 tick 去重。

静态检查：

```sh
python tools/cod4/audit.py
python tools/art/verify_ftbquests.py build/libs
git diff --check
```

常规有依赖缓存/网络的开发环境：

```sh
gradle build
gradle -I tools/cod4/cod4-test.init.gradle runGameTestServer
```

本次构建使用 Gradle 8.8 和独立缓存；环境无法由 Gradle 直连依赖站点，因此通过临时 init 脚本引用已缓存的原版/Forge 元数据和本地依赖，未把环境专用路径写入项目。服务端测试跳过客户端音画资源下载。

扩大到 `dynasty,dynasty_cod4,dynasty_infusion` 的回归执行在 100 测试批次时被终止，退出码 137，未完成，不能记为全量回归通过。可用 `-Pcod4Regression` 在资源充足环境重跑。

维护总检查仍报告基线已有的 3 个问题：`solid_handheld.json` 抽象父模型的 `#layer0`；中英文各一处 `shanyue_bracelet` 空 tooltip。已对照基线确认非本次引入。543 个配方检查无错误。

## 与原文有差异或尚未完成验收的部分

- 当前科举实现没有答题倒计时，织锦四件和状元酒改为延长答对后的增益时间 20%，没有凭空增加答题时间限制。
- 仓库没有原文所指 COD2 第 8/17/19/28/29/30 号秘密状态接口。对应互动已经接入现有结构与 FTB advancement，但尚未连接那些编号秘密或“机关城状态”。没有伪造完成标志。
- 当前基线没有按 COD3 编号的玩家公共 VFX API。反馈实现为轻量原版粒子、声音和已有渲染体系；龙纹/甲裂贴花、蝉翅、放大伤害数字以及专用倒地/起身动画没有完整实现，不能把粒子环视为这些美术效果已验收。
- 模型使用现有原生材质图集，物品复用原版/现有图标。七态动画和分段骨骼的结构已检查，尚未完成客户端逐只美术、持握姿态与动作观感验收。
- 互动采用计时、供品与多次操作的轻量实现；义庄辨认、毒茶和月下舞剑没有完整的叙事/谜题场景。
- 配方解锁指原版配方书发现，不是 JEI 隐藏配方或禁止提前合成；原有装备不会因未完成任务而被禁用。
- 未完成真实双客户端联机、完整整合包启动、FTB 客户端页面点击和同屏 20 怪帧率实测。专项 FakePlayer 测试不能替代这些验收。

因此，本分支提供可构建、已通过专项服务端验证的 COD4 实现；上述缺口和未验收项应保留为明确后续工作，不能宣称需求原文逐项 100% 完成。
