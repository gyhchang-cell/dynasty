## ② 招什么人 / 怎么上手

| 角色 | 上手要看的东西 | 第一条能产出的任务 |
| --- | --- | --- |
| Java / Forge | `src/main/java/com/dynasty/`、`docs/开发约定.md` | 给某个 Boss 加一个新技能（照着 `DynastyBosses` 里现成的抄） |
| 美术 | `tools/art/gen_*.py`（贴图是脚本画的，改脚本就行） | 重画一套甲胄贴图（改 `gen_armor2.py` 的配色表） |
| 任务 / 文案 | `tools/art/gen_ftbquests.py`（一章 = 几条线） | 给一章加 3 条支线任务 + 副标题 |
| 数值 | `DynastyBalance.java`、`DynastyWeapons.java` | 调整中期武器曲线（改数字 → 一键重跑） |
| 测试 | 直接跑整合包 | 按「崩溃报告 + 复现步骤」提 issue |
| 翻译 | `lang/en_us.json` | 把某一类物品的英文润色一遍 |

**开发环境（三步）**

```bash
git clone <仓库>
cd dynasty
./gradlew build          # 编译 + 自检
./gradlew exportModpack  # 生成整合包 + 同步到 HMCL 实例（可改成你自己的路径）
```

## ③ 给新人 / 给 AI 的提示词（直接复制）

### A. 项目上下文提示词（贴给任何 AI，让它按我们的约定干活）

```
你在协助开发 Minecraft Forge 1.20.1 模组「Dynasty 王朝」（modid: dynasty）。

【项目结构】
· 源码：src/main/java/com/dynasty/（Dynasty.java 是主类；DynastyTabs 创造物品栏；
  DynastyWeapons/DynastyGear 兵器装备；DynastyBalance 数值总表；
  DynastyCombatEvents 战斗结算；DynastyTrinkets 饰品；entity/ 怪物与 Boss；
  block/ 方块；structure/ 结构；worldgen/ 地形；client/ 提示与指南）
· 资源：src/main/resources/assets/dynasty/（贴图模型语言）、
  data/dynasty/（配方、维度、生物群系、结构、成就）
· 生成器：tools/art/*.py（贴图、模型、配方、语言、任务书、文档全是脚本生成的）
· 自检：tools/art/verify_modpack.py / verify_ftbquests.py / verify_worldgen.py
  / verify_feature_order.py，跑 `./gradlew exportModpack` 会全部执行

【必须遵守】
1. 注释与文档用中文，关键处补一行英文；不要删掉已有的中英双语注释风格。
2. 不使用 mixin；需要绕过原版限制时用 Forge 事件 + 反射（参考 DynastyAttributeCaps）。
3. 数值集中写在 DynastyBalance（套装/怪物减伤/特攻），不要在别处硬编码。
4. 新增方块/物品必须同时给：注册、模型 json、贴图 png、配方、中英词条、
   创造栏登记（DynastyTabs）、图鉴说明（DynastyCodex*）。
5. 世界生成改动后必须跑 verify_worldgen.py 与 verify_feature_order.py。
   - 噪声 id（如 minecraft:netherrack）是 worldgen/noise，**不是方块**，别一起替换；
   - 同一个维度里加特征要注意 FeatureSorter 的先后顺序，两个生物群系里
     同一对特征的先后必须一致，否则 `Feature order cycle found` 直接崩。
6. 任务书：一章 = 若干条「线」，线首用 branch=True；前置只留「配方 / 章节入口 /
   剧情门槛」三类，不要用「接上一条」把任务全串死。
7. 改完给结论：先说要改哪些文件、为什么；再给完整可编译的代码；最后说明怎么验证。

【产出要求】
· 给出完整文件内容或精确 diff，不要省略（…）和占位符；
· 不要引入新的第三方库（项目只用 Forge 自带 + Curios/FTB 这些已有依赖）；
· 任何破坏存档兼容的改动要显式提醒。
```

### B. 让 AI 帮你加一个功能

```
在「Dynasty 王朝」模组里加一个功能：<一句话描述>。

步骤：
1. 先读相关文件（列出你要读哪些），告诉我现在是怎么实现的；
2. 给出实现方案（改哪些文件、新增哪些文件、数值放哪里）；
3. 输出完整代码（中文注释 + 英文一行）；
4. 说明验证方式：需要跑哪些自检脚本、进游戏怎么测（给具体步骤）。
要求与项目约定一致（见「项目上下文提示词」）。
```

### C. 让 AI 帮你画贴图（贴图是 Python 脚本生成的）

```
tools/art/gen_armor2.py 里有一套甲胄贴图生成器（用 artlib.Cv 逐像素画 32x32）。
请给「<套装名>」设计一套新配色：主色 <色值>、边缘 <色值>、点缀 <色值>，
输出可以直接替换进去的 SETS 配置行，并说明生成后要去哪看效果
（python3 tools/art/gen_armor2.py，然后看 src/main/resources/assets/dynasty/textures/item/）。
保持和现有几套一致的画法（描边、明暗层次、纹样），不要引入新依赖。
```

### D. 让 AI 帮你加任务

```
任务书生成器：tools/art/gen_ftbquests.py。
请在第 <N> 章（CH<N>）里加一条新的「线」：
· 线首用 branch=True；
· 中间任务用 I("物品名", 数量, desc="...")（物品 id 必须是 lang 里真实存在的）；
· 需要剧情门槛时写 extra=["dynasty:某物品"]；
· 目标：<描述，比如「让玩家知道去地府要带归乡符」>。
输出可直接粘贴的代码段，并说明跑 python3 tools/art/gen_ftbquests.py 后
如何用 verify_ftbquests.py 确认没出问题。
```

### E. 让 AI 帮你查崩溃

```
崩溃报告在下面 / 日志在下面。请：
1. 直接指出根因（哪个 mod、哪个文件、哪一行数据）；
2. 说明为什么会导致崩溃；
3. 给出最小修改方案（别顺手重构）；
4. 如果这是「以后还会再犯」的坑，顺便建议加一条自检规则。
崩溃报告：
<粘贴 crash-report 前 60 行>
```

请给出具体数字改动表（旧值 → 新值）和理由，并指出哪些是「会被原版上限夹掉」的无效改动。
