# 镇渊终战与原创巨型建筑

本次内容直接包含在 Dynasty 本体中，不需要额外建筑模组。使用 Minecraft 1.20.1 / Forge 47.4.10。

## 本轮完成的内容

- 五座低矮、自带不同碰撞形状的供台。每台上方有透明供物球、贡品名称和右键提示。
- 正确供奉后，贡品悬浮显示，台面亮起并展开四瓣，光线汇向中央。
- 中央混元珠展示与旋转金球放大约 50%。金球是实时三维几何，不是金块堆成的雕像；四象轨道和上下符环随进度增加。
- 供品齐全后聚能五秒，祭坛上层消隐，进入独立的镇渊终战维度。龙体、原平台和安全地板保留。
- 镇渊帝君有三个阶段：环形震荡、落点冲击、交叉封锁，攻击有预警和可躲避区域，不炸毁方块。
- 战胜后三秒返回原祭坛中心，朝向恢复到供奉时方向，奖励进入前方宝箱。无法安全落脚或宝箱位置被占用时不覆盖玩家建筑。
- 龙头战后外观暂不变，已经提供 `ZhenyuanVictoryEvent` 接口。等设计确认后再接视觉变化。

## 建筑已加入整合包，怎样在游戏放置

请先备份世界，选择完全空旷的大区域。命令仅限管理员；不需要 WorldEdit。

```text
/dynasty_build longque_sanctuary
/dynasty_build longque_sanctuary confirm

/dynasty_build yunqi_manor
/dynasty_build yunqi_manor confirm
```

不带 `confirm` 的命令只显示说明。放置从脚下高度向北展开，东西居中；请不要站在别人的建筑附近确认。

- 龙阙镇渊：1,872,624 个实际方块；原龙为 1,799,177 块，另加口内平台与低祭坛。实占 226×191×254，预览画布 228×192×256；导入只裁掉外围空白，不改变实际方块或比例。
- 云栖庄园：1,975,829 个实际方块，实占 451×120×517，预览画布 452×122×518。此处指本任务原创三维模型中的云栖庄园，不是覆盖用户手工建造的院子存档。
- 先进行整片空间预检，再分批放置；固体完成后再放水。发现现有方块、实体占位或高度越界会停下，不挖掉原地形或已有建筑。
- 巨型建筑需要较长时间施工。不是一次性 `/fill`，也不是每生成一个区块就同时塞入数百万方块。
- 龙头放置完成后，五座供台自动绑定仪式。无需再对龙嘴使用 `place`，也不要重叠放置第二份祭坛。
- 本轮是显式放置入口，未加入高频自然生成；不会自动在用户现有存档里刷出建筑。

进度管理：

```text
/dynasty_build status
/dynasty_build cancel
/dynasty_build resume
```

`cancel` 是暂停，保留已经完成的方块；`resume` 校验资源和检查点后续建。`abandon confirm` 仅丢弃施工记录，不删除世界里的建筑。断电后的模糊归属会保守暂停，绝不把不确定是否属于玩家的方块强行认领或删除。

## 只测试祭坛和终战

在空地站定后，由管理员运行：

```text
/dynasty_ritual place
```

安装本体约 60×12×60，占用现有建筑的位置会拒绝安装。站立位置是将来的返回中心；只本次记录为新建的祭坛上层会消失。

普通玩家可以使用：

```text
/dynasty_ritual status
/dynasty_ritual escape
/dynasty_ritual resume
/dynasty_ritual claim
```

终战中致死伤害会安全撤离并保留物品，没有失败奖励。退出、掉线和恢复时保存挑战与 Boss 状态。奖励仅在确认通关后生成一次；箱子被取空或拆掉不会重填。宝箱位置受阻时，清空提示坐标后用 `claim` 重试。

## 预览与实装的区别

- 本地网页按钮只是视觉演示，不消耗游戏物品、不传送玩家。
- 球体、光环和供奉动画由本体的方块实体渲染器实时绘制，不存在于 `.schem` 的方块列表中。
- 单独导入 `.schem` 不等于完成仪式绑定；游戏请使用上面的本体命令。
- 本轮不触碰用户手工建造存档，不自动同步或替换正在运行的实例。安装新包后需要完整重启游戏，不能仅靠 F3+T 加载 Java 逻辑与新维度。
