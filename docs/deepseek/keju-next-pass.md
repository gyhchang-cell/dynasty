当前实际缺口（仍须以开工时源码复核）：

1. `KejuScreen.init()` 固定 240 宽按钮、固定纵坐标；题干只画一行，长题干/长选项和小窗口缺少可靠排版。没有题面滚动与专门的数字键选择逻辑。
2. `DynastyKeju.handleAnswer()` 先 `PENDING.remove()`，再比较令牌。错误或过时答题包会清掉玩家当前有效题目；`choice` 也没有先校验为 1..3。
3. 当前令牌是 `tierIndex * 1000 + index`，同题会重用；会话只存整数，判分时重新按题库下标找答案，没有固定住开题时的题目快照。
4. 题库缓存只在 `MinecraftServer` 对象改变时重读，同一服务器 `/reload` 后不会自动采用新题库。静态待答与奖励冷却表也缺少完整生命周期管理。
5. Java 加载器会把错误答案下标静默改成 1、接受四个以上选项后截前三个，并自动排序门槛；这和现有 Python 检查的严格程度不一致。Python 检查对错误类型、空白字符串、布尔值冒充整数等也还不够稳健。

### 2. 做出三项有实效的改进

#### A. 可阅读、可操作的考试界面

- 使用现有字体和 `GuiGraphics` 做克制的国风试卷面板：标题、题干区、三个选项区、操作提示有明确间距和层级；不生成新 PNG，不加背景大图，不做满屏粒子。
- 题干、选项按实际字体宽度换行；按钮高度随内容增长。布局按窗口逻辑尺寸缩放，必要时提供可访问的滚动区域；不能通过截掉题目或把字缩到看不清解决溢出。
- 鼠标点击选中选项，数字键 1/2/3 选中，Tab/方向键和 Enter 能完成作答。增加明确的“确认作答”按钮，未选择时不可提交；同次界面最多发送一次答案包，防止连点。
- Esc 关闭不判错、不发奖励。保持 `isPauseScreen() == false`，保持原有试卷右键与 `/dynasty keju` 打开方式。
- 本轮没有新增结果回包，不要在客户端假装知道答对/答错。提交后沿用服务端现有聊天判分反馈；不要用聊天文字解析伪造确认协议。
- 复用已有翻译键；科举内部新提示可先沿用本模块现有中文写法。需要全局新增语言键时只在交付报告列出建议，不能改全局语言文件。

#### B. 服务端一次性答题会话

- 将整数下标映射改为明确的会话对象：服务端生成的本次令牌、所属玩家 UUID、开题时题目与档位奖励快照、创建时间。客户端仍只提交令牌与 1..3 选项，不能提交正确答案、奖励值或档位。
- 令牌在同一服务端生命周期内避免复用；不要再让它可反解题目下标。保留外部 `openExam(ServerPlayer)`、`pending(Player)` 和 `handleAnswer(ServerPlayer,int,int)` 接口，管理员 `/dynasty answer <1-3>` 无须改动。
- **先验证，再消费**：无会话、错误令牌、非法选项、其他玩家的令牌不得获得奖励，也不能吃掉当前合法会话；只有令牌及选项都合法的一次提交才消费该会话。正常答错依然结束本次题目。
- 同一玩家重新开题会替换旧会话；旧包不能影响新题。断线清理待答会话，服务端关闭清理所有临时会话和该服务端缓存。
- 不擅自加入倒计时、每日次数、考试费用、必须在国子监答题、多人竞赛等新玩法；本轮不改变原来的答题时长限制（目前没有限时）。
- 冷却不能被 `/reload`、关界面、重开题或断线重连绕过。登出时不能直接抹掉仍在 30 秒内的奖励时间；已过期条目可清理，避免无限积累。
- 在两个现有包的 handler 内核对网络方向：打开题目只接收 PLAY_TO_CLIENT，提交答案只接收 PLAY_TO_SERVER。仍从上下文读取真实发送者，在正确线程处理，不信任客户端自报身份。
- **保持现有线协议**：Open 包仍是一个 int 加四个字符串，Answer 包仍是两个 int。可明确字符串长度上限并与题库/UI 校验一致，但不能增减字段、注册新包或改通道版本。对非法包安全拒绝，不能使服务器崩溃。

#### C. 严格、可重载的题库

- 保留 `data/dynasty/keju/questions.json` 格式和全部现有 45 题，题目仍从该 JSON 加载。题库编辑不是本轮目标。
- Java 加载器与 Python 检查统一：档位 ID 唯一且非空、中文/英文名称非空，门槛为非负整数并严格递增，奖励为正整数，每档至少 10 题；题干和三个选项均为非空字符串、选项互不重复、题干全库不重复，答案必须为真正的整数 1..3。不能接受布尔值作为整数。
- 定义合理的题干/选项长度及题量上限，用同一份说明解释 Java、网络和验证器之间的关系；不要靠现有 `tier*1000` 编码隐含限制题数。
- 错误必须指出题库路径、档位、题目位置和原因。禁止静默改正确答案、截选项、重排坏门槛。校验失败时整份新题库不生效，使用上一份有效题库；首次加载没有有效题库时回落到现有七题兜底。缺文件也要清楚记录，不让玩法崩溃。
- 用 Forge 现有服务端数据重载事件/监听器接入 `/reload`，可新增科举专属事件类；不要去改全局主类或已有悬赏的监听器。可只读参考 `bounty/BountyService.java` / `BountyOffers.java` 的事件接法，但不要复制悬赏业务。
- 一次重载成功后，新开题使用新题库；**已经打开的题目仍按其不可变快照判分和发放原档位奖励**，不得因题库排序/删题变成另一题。重载失败不破坏正在进行的会话，不重置奖励冷却。
