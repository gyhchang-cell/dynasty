## 实现与生成

- `tools/art/gen_curios.py`：169 件饰品分类、标准槽定义、万能槽定义和玩家槽配置。
- `tools/art/gen_ftbquests.py`：任务文案、节点、奖励；同时生成 `data/dynasty/curios_progression.json`，供 Java 查找任务。
- `DynastySlotProgression`：个人永久解锁、死亡复制、FTB 反射补发；管理命令 `/dynasty unlock_curio <milestone>` 需要 2 级权限，FTB 临时提权执行。
- `DynastyCuriosBridge`：仅修改本模组固定 UUID 的永久槽位修饰符，不清空其他模组的加槽奖励。
- `verify_gear.py` 已接入 `verify_curios.py`，原导出流程的装备自检也会检查分类与里程碑。

不要把所有饰品加到 `curios:curio` 物品标签：Curios 5.14.1 的标签谓词会让这些物品进入任意分类槽。
万能槽通过独立的 `dynasty:accessory` 校验器接纳饰品，分类槽仍使用自己的标签。

## 饰品效果格式 v2（第三十四轮起）

饰品是**表驱动**的：真源在 `tools/art/gen_trinkets*.py` 的 `TRINKETS` 表，
`DynastyTrinkets.EXTRA_TABLE` 必须逐行对应（`tools/art/verify_gear.py` 会把两边并起来核对，
另外还要核 Curios 标签、贴图、模型、配方、中英词条六处齐全）。

一行最多 **15 格**：

```
{id, 属性1, 值1, 属性2, 值2, 效果, 等级, 条件, 属性3, 值3, 条件3, 命中触发, 数值, 概率%, 连携组}
```

* 前两格属性共用第 8 格的 `条件`；
* **第三格属性带自己的 `条件3`** —— 这是 v2 的关键：一件饰品可以「白天 +22% 攻击、夜里 +10% 移速」；
* 第 12~14 格是 **命中触发**（`DynastyTrinketOnHit`），0 = 不带；
* 第 15 格是 **连携组**（`DynastyTrinketLink`），0 = 不参与；
* 老行（8 格 / 11 格）照旧生效（Java 按 `row.length` 判断）。

编码表（生成器与 Java 必须一致）：

* 属性：`0 生命` / `1 护甲` / `2 抗击退` / `3 移速%` / `4 攻击%` / `5 攻速%` / `6 击退` / `7 距离` /
  `9 生命上限%` / `11 幸运`；`-1` = 这一格空着。
* 效果：`21 龙威` / `22 铁壁` / `23 疾风` / `24 威慑` / `25 天命` / `26 忠诚` / `27 内伤` ——
  全是**模组自有效果**，「内伤」反过来当代价用；`0` = 不带效果；`1~12` 是旧批次用的原版效果，新饰品不用。
* 条件：`0 常驻` / `1 白天` / `2 夜晚` / `3 水下` / `4 残血（<40%）` / `5 骑乘` / `6 满血` / `7 雷雨`。
* 命中触发（第 12 格）：`0 不带` / `1 吸血`（数值 = 按伤害回血的比例）/ `2 斩杀`（数值 = 血线，
  玩家与 Boss / 神兽、血量上限 > 80 的目标免斩）/ `3 会心`（数值 = 额外伤害倍率）/
  `4 突袭`（只在目标满血时生效）/ `5 连击`（数值 = 每层倍率，3 秒内最多 6 层）/ `6 雷罚`（数值 = 附加伤害）。
  第 13 格是数值、第 14 格是概率（%）。前 11 格的 `条件` 对命中触发不生效：命中是「打的时候」判定。
* 连携（第 15 格）：`0 不参与` / `1 昼夜双生` / `2 生死代价` / `3 天朝敕令` / `4 幽冥献祭` / `5 巧匠边塞`。
  同组**同时佩戴 2 / 3 / 4 件**触发对应档位，**只取达到的最高档、不叠层**；
  加成写在 `DynastyTrinkets.LINK_TABLE`（`{组, 需要件数, 类型(0 属性 / 1 模组效果), 编码, 数值, 条件}`），
  由生成器打印后粘进去，`verify_gear.py` 会核对「生成器 ↔ Java」三方一致。
  例：天朝敕令 2 件 = 幸运 +2，3 件 = 幸运 +3 + 生命 +200，4 件 = 常驻龙威 + 攻击 +10%。

写法示例：

```
{"dawn_blade_charm", 4, 0.22D, -1, 0D, 0, 0, 1, 3, 0.1D, 2},   // 白天攻击 +22% / 夜里移速 +10%
{"blood_oath_seal",  9, -0.3D, 4, 0.35D, 0, 0, 0, -1, 0D, 0},  // 生命上限 −30% 换攻击 +35%
{"internal_injury_talisman", 4, 0.45D, -1, 0D, 27, 0, 0, -1, 0D, 0}, // 攻击 +45%，代价是常驻内伤
```

两条硬约束（UUID 分段与自检都依赖它们）：

1. 同一件饰品的三格属性用三段 UUID（`uuid(id, 0~99)` / `100~199` / `200~299`），
   所以同名属性可以两格各加一次而不会互相覆盖；`clearAttrs` 三段一起清。
2. 「生命上限 %」用编码 9（`MULTIPLY_TOTAL`），**不要**用编码 0 扣一大笔固定生命 ——
   属性会被钳到最低 1 点，穿一件就可能直接空血。

加一批饰品的流程：写 `tools/art/gen_trinketsN.py`（照抄 `gen_trinkets5.py` 的结构）→
运行它（顺便生成贴图 / 模型 / 配方 / 词条 / Curios 标签，并打印 `EXTRA_TABLE` 行）→
把打印出来的行粘进 `DynastyTrinkets.EXTRA_TABLE` → 补 `gen_curios.py` 的 `GROUPS` 分槽 →
补 `gen_ftbquests.py` 的 `_TRINKET_EXTRA*`（并进既有 5 类，别新开列）→
`./gradlew jar`（自检从 jar 里查物品，**必须先 jar**）→ 跑自检。

悬浮说明也是表驱动的（`CharmItem.appendHoverText`）：`[白天] 攻击 +22% · [夜晚] 移速 +10%`、
`效果：龙威 I`。**加新编码时同步 `attrText` / `effectName` 两个 switch**，否则那一格会安静地不显示。
（早期 39 件「手写效果」的老饰品没有 tooltip，这一批表驱动饰品全部有。）
