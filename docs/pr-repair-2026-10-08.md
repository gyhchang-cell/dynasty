## Resolution decisions

- Language files are key unions of both parents, with strict duplicate-key rejection, matching English/Chinese keys and Minecraft format arguments. No divergent same-key translation required dropping an implementation. Integration has 1411 paired keys.
- PR10 retains main's expanded mob kinds, rendering, animations, combat and encounter bindings alongside the source's ecology factions, predation, world events, dungeon geometry and tests. Exhaustive animation switches cover the merged enum. A duplicated identical spawn method from automatic merging was reduced to one implementation. The ecology test now checks actual registry availability, including main's newly available creature, instead of asserting that creature is missing. A null fixture assertion prevents a diagnostic failure from crashing the entire GameTest server; tests were not removed.
- PR12 retains main and cod3 translations, world/structure additions and boss sequences. Army encounter actors retain exclusive encounter ownership of death, first-kill and rewards instead of receiving a second cod3 reward flow. A regression test covers that ownership boundary.
- PR13 retains main and cod4 translations and equipment/mob behavior. Projectile weapon selection retains cod4's firing snapshot, the existing star-arrow snapshot and cod6's progression snapshot, with the legacy held-item fallback for untagged arrows.
- PR14 combines main's reachable ceiling-spider gallery with cod6's solid mirrored ore benches, access routes and quarry chests. New quarry geometry is layout 6. Layouts <=3, main layout 4 and already-saved cod6 layout 5 keep their respective factories, so remaining chunks of an old structure do not silently use new geometry. Rotation, saved-NBT and actual generated-cell assertions cover the boundary. The existing final-boss test now expects cod6's authored 90000 health while retaining phase/persistence checks.
- Existing FTB quest, task, reward and dependency identities are retained. Generated recipe descriptions were refreshed from merged recipes. cod6's six existing army-clear quest task migrations and descriptions are represented in the generator, so regeneration preserves them. Other legacy kill tasks are not converted. Existing modpack configuration was preserved.

## Network compatibility

All sources previously reused protocol 8 with independently appended packet IDs, making equal version strings unsafe. The common base IDs 0–11 are retained. Independent common-setup registration files assign:

| ID | Extension | Direction |
| ---: | --- | --- |
| 12 | cod3 visual | server to client |
| 13 | cod6 edict cast | client to server |
| 14 | cod6 edict visual | server to client |
| 15 | cod1-3 world event state | server to client |
| 16 | cod4 combat feedback | server to client |

Protocol 9 advertises a sorted schema of IDs, payload class, direction and wire revision. Both sides require exact schema equality. Duplicate or reserved extension IDs fail registration. A partial cod3 build cannot accept a partial cod6 peer merely because both report the same base version. GameTests verify schema and incompatible-peer rejection; cod6 also checks payload round trips. This does not certify a live multiplayer session.
