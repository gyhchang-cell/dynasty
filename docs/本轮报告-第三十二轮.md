## ④ 性能与稳定性

饰品系统原来每秒对每个玩家做这些事（`DynastyTrinkets.tick`）：

1. **7 次全量扫描**：`tick()` 里 6 处 `has(player, "...")` + `apply()` 里的 1 次，每次都要扫
   41 格背包 + 副手 + Curios（反射桥接）；
2. **119 件饰品 × 8 个属性 = 约 950 次属性操作**，**空手玩家也照跑**（`for (String id : IDS) clearAttrs(...)`）；
3. 每个格子的 id 判定用 `List.contains`（O(n)），筛选用 `out.retainAll(IDS)`（List）。

| 改法 | 效果 |
| --- | --- |
| `activeIds()` 结果按 `tickCount` 缓存 | 同一 tick 内复用 → **扫描 7 次 → 1 次**（背包不可能在同一 tick 内变） |
| 只清「上一轮真正加过」+「本轮新出现」的饰品 | **约 950 次属性操作 → 等于身上饰品数**（空手 = 0 次），仍保留「先清再加」的幂等语义 |
| `IDS` 增加 `Set` 视图（`ID_SET`）+ 跳过空格子 | 判定从 O(n) 变 O(1)，省掉空格子的注册表查询 |
| 登出事件 `DynastyTrinkets.forget(player)` | 清掉三张缓存，长服不攒废条目（是新加的事件处理器） |

* 语义不变的依据：同一 tick 内 `tickCount` 不变 → 缓存必然命中同一次扫描；跨 tick 自动失效。
* **需要你实机确认**：装 0 件 / 装满饰品两种情况各跑几分钟，看 TPS 与饰品效果是否照常
  （建议用 spark 或 F3 观察；我这边只能做代码级核算，给不出帧率数字）。
