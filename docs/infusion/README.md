# 现有材料炼入装备 · cod5

基于 main `86c3d2a` 继续实现 Forge 1.20.1 炼入系统。沿用原 `infusion_table`、`infusion` 菜单及原材料；95 件现有材料映射到 40 种行为效果（21 进攻，19 防护/符法）。未增加宝石物品或第二套工作台。

完整映射见 [material-mapping.tsv](material-mapping.tsv)，运行定义为 `data/dynasty/infusion/materials.json`。每行包含原中文名、类别、适用装备、效果、容量、材料数量、冲突组、本地化键、反馈和真实来源引用。来源中保留原物品 ID、名称、模型贴图、配方、掉落数量及创造栏顺序。弩箭、刷怪蛋等实际功能物品不作为材料。

## 使用

取得玉并获得炼入台后，右键放入装备和材料。界面从左到右为装备、材料、不可取出的结果预览；默认自动选择空炼入位。三枚纹章悬浮显示效果，点击选中后可替换或移除，再点取消选择。

每次炼入/替换消耗 2 件相同材料和 3 级经验；移除消耗 1 级经验且不返材料。创造模式免材料、经验和进度要求。最多 3 个特性；普通装备容量 3，稀有装备或耐久≥8000 容量 4，史诗装备或耐久≥45000 容量 5。同效果及冲突组不能叠加。旧版合法四容量装备继续生效，新写入按当前容量限制。

防具、盾和饰品接受防护/符法特性；武器接受进攻特性，近战专属与弓弩专属效果会单独检查。饰品仅在实际 Curios 槽位生效。背包中存放装备不触发。普通提示只显示效果名，Shift 展开机制；JEI 为每种材料提供一条说明，无装备组合膨胀。

输入槽由同一方块实体保存，关界面或退出后留在工作台；拆除掉出一次。多个玩家看到同一份库存。服务端核对菜单持有者、距离、方块实体、材料、等级、门槛、类型、容量和库存修订号，拒绝过期请求。结果从服务端原装备副本生成，保留附魔、名称、耐久和其他模组 NBT。

## 行为与进度

保留原24种机制，新增重击打断、中毒、背袭、夜间削弱、雷雨触发、阳炁净化、远射标记、空中缓降、阴煞凋零，以及水府护佑、濒危保护、受击反制、净毒、回生、净凋零和格挡净化。使用真实事件条件和玩家冷却，不扫描全背包、不制造额外闪电实体、不破坏地形。额外伤害上限35%；非敌对单位、盟友和玩家不能成为进攻特性目标，Boss 限制硬控制。

移除 `BlueprintSalvage` 的通用四分之一耐久修复事件，特殊护甲/工具维修材料改回原版基础材料。原版铁砧修理、既有饰品淬炼、食物效果、制作用途及旧工坊交互继续保留。FTB 首次炼入节点 ID、依赖、奖励不变，仅更新操作文字；新增获取炼入台的原版进度提示。

## 构建和验证

需要 JDK17。先运行 `python3 tools/art/make_local_repo.py`，再运行 `./gradlew build`。可用原项目打包脚本生成整合包。

静态审计：`python3 tools/audit_infusion.py`。

服务端隔离测试：`./gradlew -I tools/infusion-test.init.gradle -PinfusionTestRun=cod5-local runGameTestServer`。可用 `-PgameTestNamespaces=dynasty,dynasty_infusion,dynasty_army` 扩展回归。

真实客户端测试：`tools/infusion-qa/qa.init.gradle` 使用 `build/infusion-client/host` 和 `peer` 下的独立世界；分别运行 `runClient` 与 `-PqaPeer runClient`，同一输出目录协调两个 TCP 客户端。完成后 `-PqaResume runClient` 验证进程重启存档。测试类只在显式加载 init script 时编译，不打入发布 JAR。实际验收结果见 `validation.txt`。
