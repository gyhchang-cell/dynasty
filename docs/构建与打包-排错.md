# 构建与打包排错（Java / Gradle 相关，2026-09-18 补）

> 症状：**工程「跑不起来」「构建卡住不动」「导不出整合包」**。这份文件按「先看症状 → 直接对应操作」写。

## 0. 最省事的两条路（推荐）

| 场景 | 做法 |
| --- | --- |
| **只想要整合包** | 双击桌面 **`3-打包整合包.command`**（它调用工程里的 `打包整合包.command`） |
| **在 VS Code 里** | `⌘⇧B` → 选 **「Dynasty: 导出整合包（含本体 jar）」** |

这两个入口都会：强制用 **JDK 17** → 清掉挂起的旧 Gradle 进程 → `./gradlew exportMod exportModpack --offline`
→ 跑完自动打开 `~/Desktop/导出`，并打印四份产物的名字与大小。

## 1. 症状：Gradle「卡住 / 没反应 / 怎么跑都不动」

**真因（这次就是它）**：上一次的 `gradlew` 进程被"挂起"了（`ps` 里状态是 `T`）。
挂起的 Gradle 会一直**占着项目锁**，之后所有构建都在等锁 → 看起来像死住。

**判断**：

```bash
ps -o pid,stat,etime,command -p $(pgrep -f 'dynasty/gradle/wrapper' | tr '\n' ',' | sed 's/,$//') 2>/dev/null
# STAT 里出现 T 就是被挂起了（T = stopped）
```

**处理**（工程根目录里跑）：

```bash
./gradlew --stop                        # 停掉守护进程
pkill -f 'dynasty/gradle/wrapper'       # 清掉挂起的启动器（只清本项目，不动别的工程）
```

VS Code 里也有现成任务：`⌘⇧P` → Run Task → **「Dynasty: 清理挂起的 Gradle 进程」**。

> 另外别再让 AI 用「后台 + 重定向」的方式跑 Gradle：命令一返回，进程会被挂起（`T`），
> 于是又占住锁。要么前台跑，要么用 `start_new_session=True` 那种真正独立会话的方式跑。

## 2. 症状：报 Java 版本相关的错（`Unsupported class file major version …`）

Forge **1.20.1 必须 JDK 17**。这台机器上：

* 默认 `JAVA_HOME` = **JDK 21**（`temurin-21`），另外还装了 JDK 26 / 25 / 21 / 17 / 8；
* 工程里 `gradle.properties` 已经写了 `org.gradle.java.home=/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home`
  → **命令行跑 `./gradlew` 不受默认 JAVA_HOME 影响**；
* 但 **IDEA / VS Code 的插件**不看这个属性，所以给 VS Code 加了 `.vscode/settings.json`
  （`java.import.gradle.java.home` + `java.configuration.runtimes` 都钉 17），IDEA 里请手动把
  **Gradle JVM** 设成 `temurin-17`（Settings → Build Tools → Gradle → Gradle JVM）。

临时在终端里也可以这样跑一次：

```bash
JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home ./gradlew exportModpack --offline
```

## 3. 症状：构建「十来分钟没有任何输出」

ForgeGradle 启动时会做一次联网环境检查，网络一抖就卡在 socket 上。
`gradle.properties` 里已经关了它（`systemProp.net.minecraftforge.gradle.check.certs=false`）；
如果还是慢，先确认用的是 `--offline`（依赖都已在本地缓存里）。

## 4. 症状：导出的包里是旧内容

* `verify_ftbquests.py` 的「物品是否存在」是**从构建出的 jar 里读的**（`build/libs/dynasty-*.jar`）。
  只改资源不重新构建 → 自检会误报「物品 xxx 不存在」。
  所以流程永远是：**先 `./gradlew jar`（或直接 exportModpack），再跑自检**。
* `exportMod` 才会刷新 `~/Desktop/导出/Dynasty模组/dynasty-1.4.0.jar`，
  `exportModpack` 只出三种整合包 —— 一键脚本里两个任务都会跑，所以两边都是新的。
