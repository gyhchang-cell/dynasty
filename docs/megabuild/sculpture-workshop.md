# 原创龙阙与云栖庄园：安全分批安装

这一批加入的是我们自主创作的张嘴龙阙模型、低供台祭坛，以及当前建模预览中的**云栖庄园**，不是玩家手工院子的替代品。不会改动玩家原存档、院子、龙的已存世界位置，也不会默认把巨型建筑随机生成到世界里。

## 包含的建筑

| 命令 ID | 实占尺寸（X×Y×Z） | 非空气方块数 | 内容 |
| --- | --- | ---: | --- |
| `longque_sanctuary` | 226×191×254 | 1,872,624 | 原龙完整保留，嘴内平台、低供台与真正可交互的五灵祭坛 |
| `yunqi_manor` | 451×120×517 | 1,975,829 | 原创建模云栖庄园，屋顶、院落、内饰、水池与土地基础 |

原始预览分别是 228×192×256 和 452×122×518；安装资源仅裁掉外围纯空气边，不删任何原有实物体素。金球和透明供品球由方块实体渲染器连续绘制，不会被转换成金块/玻璃立方体。中央金球半径 0.975→1.65 格，轨道随四象供奉出现；中央混元珠也放大。

## 怎么放置

先备份，再在超平坦空地、创造模式站到打算放置建筑的南侧边缘。模型底层从玩家脚部高度开始，X 方向以玩家为中心，整体向北（负 Z）展开。

```text
/dynasty_build longque_sanctuary
/dynasty_build longque_sanctuary confirm

/dynasty_build yunqi_manor
/dynasty_build yunqi_manor confirm
```

不带 `confirm` 只显示说明。命令需要管理员 2 级权限。主世界顶部为 Y=319 时，龙底层不能高于 Y=129，庄园不能高于 Y=200；代码还会根据实际目标维度的上下限检查。禁止安装到专用最终战场维度。

请留出完整尺寸的空域；预检会检查包围盒中**所有位置（包括模型内部空气）**，不会自动铲平地面、树、山或玩家建筑。超平坦站在地面上可以把建筑底层放在草地上方。若选址不合适，先放弃记录，再换一处重试。不会跨越世界边界。

```text
/dynasty_build status
/dynasty_build cancel
/dynasty_build resume
/dynasty_build abandon confirm
```

`cancel` 是暂停；`resume` 继续。`abandon confirm` **只删除施工记录，不删除已放的建筑方块**。新建筑只能在没有旧施工记录时开始，防止两项工程冲突。

## 施工与保存安全

1. 后台解压并核对 SHA256、尺寸、全部材质索引、祭坛五节点与归属范围。无效资源在放置前失败。
2. 全包围盒空地预检分 tick 运行，不在一个 tick 扫描几千万格。
3. 每个生产 tick 最多 256 次写入、8192 次扫描，循环软预算 4ms，每步最多请求一个世界区块。Minecraft 自身区块生成、光照和磁盘保存仍可能超过此软预算，不能承诺大型生成完全没有短暂停顿。
4. 写入时重新检查原方块必须为空气，并避开玩家/生物身体。预检后有人放了新方块，也会停下，绝不覆盖。
5. 先完成所有固体，最后放水，避免池壁未完成时漏水。
6. 使用精确体素位图记录**本次实际新放置**的方块，不把“看起来材质相同”的旧方块认领为自己的。
7. 暂停/正常停服先保存区块，再保存检查点。恢复会重新核对全部资源（包括 palette 和祭坛 metadata 的 manifest SHA），并分 tick 核对世界。已经有回执且状态一致的格子可继续；有回执但磁盘仍为空气的格子可补建；未知、被玩家修改、或自然变化后的不同方块一律保留并安全暂停。

异常断电时 Minecraft 区块与 SavedData 不是同一笔原子事务。如果方块已保存但对应回执未保存，即便材质相同也会保守停止，不能保证自动恢复这一模糊归属状态。请人工核查或从备份恢复，不会为“修复”而清空区域。草方块变泥土、树叶/水自然更新也可能触发保守差异检查。

龙阙全部完成后才调用真正的祭坛绑定接口，登记本次新放置的 680 个祭坛上层格子与五个节点。保留回程地板、嘴内平台和整个原龙；献祭消隐只可处理登记归属中仍匹配的方块。绑定失败会保留建筑并暂停，不擅自修改地板。绑定接口幂等重试，不会重置已有贡品、战斗、奖励或重建已经消失的祭坛。

## 资源与可复现验证

资源位于 `src/main/resources/data/dynasty/sculptures/`，每个 ID 有 `.json` 清单和 `.vox.gz` 密集体素文件。原始来源是本任务原创模型，不包含来源不明的下载建筑。

```text
node tools/megabuild/package_sculptures.mjs
./gradlew --offline -I tools/ritual/qa.init.gradle runGameTestServer
./gradlew --offline -I tools/megabuild/sculpture-full-qa.init.gradle runGameTestServer
```

第一条对 Sponge schematic 全量回读、gzip 全量解压、裁剪体素重建后与原始每一格对比，并输出 `docs/megabuild/sculpture-resource-validation.json`。原始龙+祭坛 11,206,656 个体素与原始庄园 28,564,592 个体素（包含空气）均逐格核对。

第二条在专用 `build/zhenyuan-ritual-qa` 测试世界运行常规回归，包括负坐标遍历、回执保存、预检与临时占位、恢复、安全保留修改、每步写入预算和高度上限。

第三条是**显式启用**的真实全尺度测试，只运行 `dynasty_sculpture_full`，使用 `build/sculpture-full-qa` 独立测试世界，在空中分离位置真实放置两座建筑，再逐格读取世界（包括空气）计算 SHA256、统计方块数，检查五节点/回程地板/供台站位/左右嘴内平台。不会每次常规测试都跑数百万块生成；结果写 `build/sculpture-full-qa/verified-world.json`。不要把测试运行目录改成玩家存档。
