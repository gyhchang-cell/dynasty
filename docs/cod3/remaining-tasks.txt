## 1.0 共用框架：BossSequence（服务器权威 + 客户端播放）

不做「20 个 Boss 各写一段 tick 过场」。建立 `BossSequenceDefinition`（数据）+ `BossSequenceRunner`（执行器）。

- Step 类型（每 Step 含 `startTick`、`duration`、`params`）：
  `WAIT / PLAY_BOSS_ANIMATION / SET_BOSS_VISIBILITY / SET_BOSS_INVULNERABLE / PLAY_SOUND / SPAWN_CLIENT_VFX / SPAWN_VISUAL_ENTITY / SET_ARENA_STATE / SET_BLOCK_PRESET_STATE / CAMERA_SHAKE_LOCAL / SHOW_BOSSBAR / SET_BOSS_PHASE / SET_MODEL_VARIANT / FOG_LOCAL / LIGHTNING_VISUAL / DIALOGUE / TRIGGER_WORLD_STATE`。
- 服务器只推进 `Sequence 状态` + 广播必要事件；客户端只播放 VFX/音效/镜头局部震动。
- **玩家控制永远自由**：禁止锁 WASD、锁跳跃、锁 Camera、强制转头。不取消 InputEvent、不 `setDeltaMovement(0)`、不逐 tick `setPos`、不强制朝向 Boss。
- Boss 在 INTRO 期间：`SET_BOSS_INVULNERABLE=true`（无敌）、不开 AI（`setNoAi(true)` 或等效）、不显示 BossBar；到指定 tick `SET_BOSS_INVULNERABLE=false` + `SHOW_BOSSBAR` 才进入正常 AI。

## 1.1 通用多人/边界规则（20 套共用）

| 场景 | 规则 |
|---|---|
| 多人同时进入 | Sequence 由服务器**实例只运行一次**；后来者收到 `sequenceId + currentTick`，客户端从正确时间点续播，不重头。 |
| 晚进入 | 不重放已过 Step；只订阅当前 BossBar 与后续 VFX。 |
| 玩家死亡回来 | 不终止 Intro；复活后按当前 `currentTick` 继续。 |
| 玩家离开 Arena | Intro 继续（全世界实例级）；离开者客户端清理本地 VFX，返回时按 currentTick 续播。 |
| Chunk unload | Boss 卸载即停 Sequence；保存 `introState`（当前 Step + tick）。 |
| Server restart | 恢复 `introState`；若恢复困难，允许安全跳到 COMBAT（解锁 AI + 血条 + 无敌关闭），**绝不卡在永久无敌**。 |
| 玩家退出 | 不终止全服 Intro。 |

## 1.2 20 套 Intro 技术深化

> 每套：总 tick = 总时长；`无敌窗` = INTRO 期间；`开 AI` = 正常 AI + 血条 tick。多人/晚入/死亡/离场/卸载/重启统一遵循 1.1，不逐条重复。

### 1 玄冰破封（12s = 240tick）
- 分阶段：0-60tick 冰面龟裂（decals + 碎冰 VisualEntity，非真实替换方块）；60-140tick 破冰冲天（Boss 从潭底 anchor 上升，`SET_BOSS_VISIBILITY=true`）；140-200tick 盘旋回落四足砸地（`PLAY_BOSS_ANIMATION=landing` + 暴风雪 VFX）；200-240tick 仰天长啸 + 血条（`CAMERA_SHAKE_LOCAL=3` + `SHOW_BOSSBAR`）。
- 无敌 0-240tick；开 AI 240tick。动画 `swim_up → glide → land → roar`；移动由 anchor 垂直上升后沿预设 Bezier 落地。
- 环境：冰面「完整/破裂」两套预设 state；粒子 300-600 碎冰 + 200 白雾；音效 `block.ice.break` 密集 + 低频吼叫。
- 性能：冰面裂纹为 decal 叠加，非逐块 setBlock。

### 2 千佛石化（10s = 200tick）
- 0-60tick 石雕静立（`SET_MODEL_VARIANT=STONE`）；60-120tick 石皮龟裂剥落（按骨骼区域逐步隐藏 stone shell bones + 碎石粒子）；120-160tick 戟/眼眸亮金（variant 切 METAL + 眼部发光 layer）；160-200tick 跨下莲座踏碎 + 血条。
- 关键：**不生成独立石像再删换 Boss**；同一 Boss 实体走 variant + 骨骼 visibility。无敌 0-200tick；开 AI 200tick；碎石 200-400。

### 3 古画出渊（14s = 280tick）
- 0-80tick 壁画人物二维移动（客户端 shader/texture 动画，非实体）；80-160tick 水墨手臂撑出、Boss 沿墙法线移出（`SET_BOSS_VISIBILITY=true`）；160-220tick 泼墨 + 墨剑凝固（variant）；220-280tick 太极墨阵 + 血条。
- 关键：整面墙不做几十个实体；Boss 实体墙后隐藏，8 秒后移出。无敌 0-280tick；开 AI 280tick。

### 4 九重天棺（11s = 220tick）
- 0-60tick 锁链发红（少量链段 visual）；60-120tick 锁链崩断、棺盖飞出（无碰撞 VisualEntity，**不用高伤 FallingBlock**）；120-180tick 帝王悬空升起（`PLAY_BOSS_ANIMATION=rise`）；180-220tick 睁眼金芒 + 长袖驱雾 + 血条。
- 无敌 0-220tick；开 AI 220tick。棺盖用视觉碎片，不伤玩家。

### 5 幽潭分水（13s = 260tick）
- 0-80tick 竖瞳 + 气泡；80-160tick 分水墙（两片半透明动态 mesh/粒子面 + 局部水面 mask，**不真实移动水方块**）；160-220tick 伏波巨神踏浪上升；220-260tick 水墙坍塌 + 血条。

## 1.4 第二轮补全：真实绑定 + Step 参数 + INTRO 结束唯一条件

### 1.4.1 INTRO 结束的唯一服务器条件（防永久无敌/无AI/无血条）

> 每套 Intro 必须只由**服务器**判定结束，条件唯一且可证明：

**当且仅当以下全部满足**，服务器在同一 tick 执行 `SET_BOSS_INVULNERABLE=false` + `setNoAi(false)` + `SHOW_BOSSBAR`：
1. `sequence.currentTick >= sequence.totalTicks`；
2. 服务器 `SequenceRunner` 状态 == `INTRO`（未进入 COMBAT）；
3. Boss 实体仍在 `level` 且 `isAlive()`。

**兜底（FAIL-SAFE）**：任一条件在 `totalTicks + 40` tick 后仍未达成（Sequence 报错 / Step 抛异常 / 状态未推进），服务器强制执行上面 3 步并记日志 `[Dynasty][BossIntro] forced-to-combat boss=<id> arena=<tag>`。**绝不卡在永久 invulnerable/noAI/无血条。**

- 判定入口：`BossSequenceRunner.tick()`（`[PROPOSED]`）每 tick 跑一次，`currentTick++` 由服务器时钟驱动，不依赖客户端。
- 现有可复用：镇渊已用 `ZhenyuanRitualSavedData.Session.bossIntroTick`（0..280）作为参考，但那是**专用**字段；通用 Boss 需新增 `BossIntroState`（`[PROPOSED]`，存 persistentData 或独立 SavedData）。

## 2.0 统一死亡状态机

Boss 生命归 0 **不立即 discard**。进入 DYING：

| 状态 | 语义 | 服务器职责 |
|---|---|---|
| `LETHAL_HIT` | 最后一击命中当帧 | 记 `deathTick`、`deathSequenceId`、`rewardGranted=false`；冻结 AI、禁用攻击/受伤。 |
| `DYING` | 播放死亡演出 | 只推进 Sequence（复用 BossSequenceRunner，仅允许 Death 白名单 Step）。 |
| `DEATH_SEQUENCE` | 演出主体 | 客户端 VFX；服务器只做状态机。 |
| `REWARD` | 发奖励 | 服务端**唯一 tick 发放**，置 `rewardGranted`，写 SavedData。 |
| `CLEANUP` | 清场 | 移除临时 visual/AreaEffect/召唤物，放永久遗留物（Block/Structure），最后 remove 实体。 |

关键防重复规则：
- 奖励由服务端**唯一 tick** 发放，`rewardGranted` 标记 + 持久化；断线/重启**不重复**发。
- 掉落生成：`REWARD` 阶段一次生成 Loot/XP；`CLEANUP` 阶段不再二次生成。
- 死亡演出期间玩家仍自由移动；**不锁镜头、不全屏白屏**。

## 2.1 通用帧表（20 套都遵循，具体帧数见 2.2）

| 帧事件 | 默认值 | 说明 |
|---|---|---|
| AI 停止帧 | `LETHAL_HIT` 当帧 | `setNoAi(true)` + 清目标。 |
| Hitbox 关闭帧 | `LETHAL_HIT` + 1 tick | 不再受击（`invulnerable=true`）。 |
| 不再受伤时间 | 从 `LETHAL_HIT` 至 remove | 全程免疫。 |
| Loot 生成时间 | `REWARD` tick | 一次性。 |
| XP 生成时间 | `REWARD` tick | 一次性。 |
| VFX 时间 | `DYING`→`DEATH_SEQUENCE` | 客户端。 |
| 模型移除时间 | `CLEANUP` 起点 | 或先留 Statue。 |
| Entity 真正 remove | `CLEANUP` 末尾 | 遗留物已转 Block/Structure 后。 |

## 2.4 第二轮补全：真实死亡流程绑定 + 失败恢复

### 2.4.1 谁负责进入 DYING + 在哪拦截 vanilla death

- 现有死亡链（[VERIFIED]）：`LivingEntity.die()`（原版）→ `LivingDeathEvent` → `DynastyWorldEvents.onLivingDeath`（功名/忠诚/叛乱）→ `DynastyBossDrops.onDrops`（`LivingDropsEvent`，补掉落）→ `DynastyBossCombat.onDeath`（首杀 `getKillCredit()`）。
- 进入 DYING 的责任方：**`LivingDeathEvent`（EventPriority.HIGHEST，服务端）**，在 `DynastyWorldEvents` 之前拦截。拦截条件：`victim instanceof DynastyBossCombat.BarHolder` 或命中 `DynastyBalance.isBossOrBeast` 且带 Boss 条。
- 拦截动作：`event` 不 cancel 原版死亡，但设置 `deathSequenceId` + `deathTick` + `rewardGranted=false` + 冻结 AI/Hitbox（`setNoAi(true)` + `invulnerable=true`）；原版 `die()` 的**自动掉落与经验**用 `event` 内标志位或 `LivingDropsEvent` 里识别「正在 DYING」跳过。
- 注意：原版 `die()` 会把 health 置 0 并触发 `LivingDropsEvent`，但**不会立即 remove**（仍可延迟 remove）。DYING 演出复用这个「已死未移除」窗口。

### 2.4.2 loot / XP 防重复（[VERIFIED] 机制扩展）

- **loot 禁止原版自动生成**：在 `DynastyBossDrops.onDrops` 里加判定——若 `victim` 处于 DYING（`deathSequenceId` 非空且 `!rewardGranted`），先 `event.getDrops().clear()` 阻止原版掉落，改由 `REWARD` tick 统一生成（避免「原版掉落 + 演出掉落」双份）。
- **XP 防重复**：REWARD 只在 `rewardGranted=false` 时发放一次，发放即置 true 并写持久化；原版经验球（ExperienceOrb）在 DYING 期间不生成，统一由 REWARD tick 生成一次。
- **rewardGranted 存哪里**：BOSS 实体 `persistentData` 键 `dynasty_reward_granted`（布尔）+ 独立 SavedData `BossDeathState`（[PROPOSED]）作为断线/重启兜底；镇渊复用 `ZhenyuanRitualSavedData.Session.rewardIssued`。
- **Server restart 发生在 DYING 中途**：读 `BossDeathState`，若 `deathTick` 存在且 `rewardGranted=false` → 直接跳到 `REWARD`（补发一次）再 `CLEANUP`；若 `rewardGranted=true` → 只 `CLEANUP`（清场 + 放遗留物），**绝不二次发奖**。

### 2.4.3 LootableRemains / Statue 归属判定

- `Statue`：[NOT_VERIFIED] 当前无专用雕像块。**两种实现选一**：
  - (a) 复用现有结构 piece（`structure/DynastyStructures` 新增一个无 AI 的雕像 piece，[PROPOSED]）；
  - (b) 新增 `StatueBlock`（[PROPOSED]，`BaseEntityBlock` + 数据保存朝向/类型）。
  推荐 (a)：死亡遗留物优先走「结构 piece / 预设 Block state」，不保留死 Boss 实体。
- **Boss 实体具体在哪一 tick remove**：`CLEANUP` 末尾。顺序：`REWARD`（发奖）→ 放遗留物（Block/Structure）→ 清临时 visual/AreaEffect/召唤物 → 最后 `boss.discard()` / `remove(RemovalReason.KILLED)`。演出中途绝不提前 remove。

### 2.4.4 失败恢复策略（20 套统一，防存档卡死）

即使演出系统（Sequence/VFX/Sound）报错，也必须保证：
`正常死亡 → 正常奖励 → 正常清场`。

| 故障 | 恢复 |
|---|---|
| VFX/Sound 抛异常 | 捕获后跳过该 Step，继续推进死亡状态机，不阻断 REWARD |
| Sequence 卡死（currentTick 不再前进） | 在 `deathTick + totalTicks + 40` 强制进入 REWARD（记日志） |
| REWARD 发放异常 | `try/finally` 置 `rewardGranted`，异常后重试一次；仍失败则写 SavedData 待下次登录补发 |
| CLEANUP 异常（遗留物放置失败） | 掉落改为 `Block.popResource` 直接掉地，不因结构放置失败丢奖励 |
| Boss 卸载 / Chunk unload | `BossDeathState` 持久化 deathTick/rewardGranted；重载续 CLEANUP |

- 每套 Death 增加字段：`failRecovery`（本表策略）+ `forceRewardTick`（兜底 tick）。
- GameTest：在 DYING 中抛人工异常→断言 REWARD 仍发一次；重启于 DYING 中途→断言不双发。

## 3.0 架构

- 服务端技能只关心真实伤害形状与时间：`Shape=CIRCLE/ANNULUS/CONE/LINE/RECT/BOX/SPHERE/CHAIN/TARGET_LOCK` + `origin/direction/radius/length/width/windupTicks/activeTicks/damageTick/seed/theme`。
- 客户端 VFX 读取同一组参数画法阵/裂痕/符箓/剑阵，保证**视觉危险区 == 真实 Hitbox**。
- 通用渲染组件：`GroundDecalRenderer / RingRenderer / BeamRenderer / SplineRenderer / InstancedMeshRenderer / WorldSpaceBillboard / ParticleEmitter / ScreenEdgeOverlay / FogVolume / AfterImageRenderer`。
- 每模板统一生命周期：`SPAWN → EXPAND → SUSTAIN → COLLAPSE → END`。
- 性能：粒子按距离与设置 LOW/MEDIUM/HIGH 缩放；远处只保留主轮廓；飞剑等重复网格优先共用 mesh + 实例化；所有 ScreenEdgeOverlay 必须有 alpha 上限与 cleanup；Renderer 结束恢复 blend/depth/cull/shader 状态。

## 4.0 总原则

- 禁止重设计 30 把武器；cod1 正在实现的神器**只识别其已存在接口，不改设计**。
- 对每把现有武器查：普攻独特视觉 / 重击区别 / 连击递进 / 暴击反馈 / 格挡反馈 / 特殊机制提示 / 第一人称安全 / 第三人称正确 / 其他玩家可见。
- 缺表现的武器**复用 COD3-3 公共 VFX 库**，不许换色应付。
- 服务端只处理 damage/hitbox/knockback/state；视觉全部客户端 + 视觉包广播。

## 4.1 现状判定

| 武器类 | 现状 | 处理 |
|---|---|---|
| 普通进化链（木矛→环首刀 等） | 普攻无独立视觉，只换贴图 | 加「武器残影 + 命中火花」基础层 |
| 名器（龙渊/巨灵/青龙/霸王/雷霆/太乙 等） | 特攻有数值，无视觉 | 逐把配专属 VFX |
| 弓系（猎弓→射日/后羿） | 有弓祭礼法阵，普攻无尾迹 | 加箭尾迹 + 满蓄提示 |
| 长柄（PolearmItem） | 有距离加成，无挑击视觉 | 加挑击弧光 |
| 学院武器（镇岳刀等 8 把） | 有被动，无视觉 | 加对应流派纹 |

## 4.4 表现规范

- **禁止**仅换粒子颜色。换色 + 形状/节奏必须同时改变，否则判定为重复。
- 第一人称：所有拖尾/残影在相机 near plane 内自动裁剪，不遮挡视野、不黑屏。
- 第三人称：残影/弧线严格沿武器本地朝向，不随视角漂移。

COD3-5 Renderer 安全规范（Dynasty Weapon / Phantom / Equipment Renderer Safety Standard）
================================================================================

> 直接针对青龙偃月刀黑屏问题。所有渲染器必须遵循，违反即退回。

## 5.1 状态栈与恢复

| 项 | 规范 |
|---|---|
| PoseStack | 每次 `pushPose()` 必须成对 `popPose()`；异常路径（提前 return）也要 pop。 |
| Blend | 开启自定义 blend 前保存原状态，绘制后 `RenderSystem.disableBlend()` 或恢复原 `BlendFunction`。 |
| Depth Test | 显式 `enableDepthTest()` / `disableDepthTest()` 并用；透明巨面片绘制后必须恢复 depth test。 |
| Depth Write | 透明片/粒子面片 `depthMask(false)`；结束恢复 `depthMask(true)`。 |
| Cull | 双面片需要时 `disableCull()`，结束恢复。 |
| Shader | `RenderSystem.setShader(...)` 每次绑定正确 shader；不用 null shader；结束不残留自定义 shader。 |
| BufferSource | 使用当前 `MultiBufferSource`；`endBatch()` 后不继续写；不跨 buffer 复用 pose。 |
| RenderType | 明确用 `RenderType.eyes` / `translucent` / `cutout` / `lines`；不混用不透明与透明渲染造成遮挡。 |
| 黑屏根因 | 「giant transparent plane」覆盖全屏 + 错误 depth/blend 会吞掉主场景 → **禁用未裁剪的巨型透明片**；若必须，用 `depthMask(false)` + 明确 blend + 立即恢复。 |

## 5.2 相机与裁剪

- **camera near plane**：所有残影/拖尾/法身在 `near plane` 内自动裁剪；禁止在第一人称把拖尾画进相机前 0.1 格。
- **first-person clipping**：第一人称武器模型与特效必须在视野边缘淡出，不遮挡准星。
- **giant transparent plane**：天空裂痕/法相用世界空间 Sky/World VFX，**不是全屏黑 Quad**。

## 5.3 玩家专属视觉所有权（多人安全）

- 禁止：玩家 A 触发视觉后，玩家 B 客户端错误进入相同 Camera/Overlay 状态。
- 实现：Camera/Overlay/Fog/ScreenEdgeOverlay 一律绑定**玩家 UUID**，只对该玩家本地生效；视觉包只携带「世界空间 VFX」给附近 32 格，不携带「相机/覆盖层」状态。
- 断线/切维度/离开区域后，本地 Camera/Overlay 必须强制恢复默认。

## 5.4 强制验收

1. 青龙偃月刀第一/第三人称挥砍不黑屏。
2. 双人联机：A 持刀触发神影，B 视角不黑、不进入 A 的 Camera/Overlay。
3. 切维度、传送、死亡复活后渲染状态恢复。
4. 低配（LOW 粒子）下无残影遮挡、无透明片吞场景。

- 左：输入材料；中（最大区）：内部液体 Tank 按真实液量比例填充；右：燃料/温度；容器交互槽（桶/罐）；模式按钮：自动/仅灌入/仅抽出（确有需要才加）。
- 悬停液体区显示液体名/mB/容量；多液体按层显示，切换输出由服务器验证。无液体机器禁止硬加 Tank。

### D. RITUAL/INFUSION 祭炼/神性灌注型
- 中：目标物/核心；四周：贡品/催化槽；外圈：四象/神性进度；右：输出/结果预览。危险祭炼加稳定度/失败风险，不做随机无解吞物。

## 7.3 架构（每台机器）

`MachineBlock / MachineBlockEntity / MachineMenu / MachineScreen / MachineRecipe(RecipeType/Serializer) / MachineDefinition` + 需要时 `FluidHandler/ItemHandler`、`ContainerData/DataSlot`、`ServerboundMachineButtonPacket`。

- 右键：服务端确认 BlockEntity → openScreen/MenuProvider → 客户端开 Screen（客户端不自己开假 UI）。
- BlockEntity 保存：inventory / progress / maxProgress / selectedRecipe / fluid tank / fuel / temperature / state / customName。纯 UI 动画状态不写 NBT。
- Menu 负责 Slot 布局 / mayPlace / mayPickup / shift-click / stillValid 距离 / 数据同步 / 按钮权限。
- Screen 只负责背景/图标/进度条/槽位高亮/tooltip/液体温度显示/按钮；不直接改真实库存。
- 任何按钮点击发服务端包，服务器重新验证玩家仍开此 Menu + 位置正确 + 按钮合法才改 mode。

- `SecretDefinition`：`id / scope(WORLD|PLAYER) / dimension / structure|biome tag / requiredTime / requiredWeather / requiredItem / requiredWorldState / triggerType / oneTime / cooldown / reward / revealMethod / debugName`。

- TriggerType：`INTERACT_BLOCK / BREAK_BLOCK / HIT_TARGET / USE_ITEM_AT_POS / ENTER_REGION / TIME_WINDOW / WEATHER_WINDOW / KILL_ENTITY_AT_REGION / PLACE_ITEM / PLAY_INSTRUMENT / READ_PATTERN / EQUIPMENT_CHECK / WORLD_STATE / COMBINATION`。
- 线索不进任务书内部 ID；只给环境线索/NPC 暗示/物品描述；调试命令可看条件，正式玩家不可见。

### 10.3.1 条件核查（[NOT_VERIFIED] 条件必须替换，不为此新造系统）

- **无 Season 系统**（[NOT_VERIFIED]）。原「春季/秋季」→ 改用 `dayTime`（一天内）或 `worldState`（世界状态）。
- **无 Fog Weather 系统**（[NOT_VERIFIED]）。原「雾天气」→ 改用 `raining`/`thundering` 或区域 fog 参数；若坚持真雾则标 `REQUIRES_NEW_SYSTEM`。
- **可真实判断条件**（[VERIFIED]）：`gameTime / dayTime / moonPhase / raining / thundering / biome tag / altitude(Y) / worldState / structure proximity`。
- 修订：奇观 3/18「雾」→ `raining`；7「春季第一场夜雨」→ `moonPhase==FULL && raining`；19「秋」→ 固定 `dayTime` 黄昏段；13「夜晚」保留（真实 `isNight`）。

### 10.3.2 25 奇观实现字段（统一模板，禁止超远巨型 AI Entity）

| 字段 | 约定 |
|---|---|
| visual anchor 算法 | 服务器选 anchor：结构中心 / 玩家视野方向 96-128 格外 / 固定结构 marker；seed 固定可复现 |
| 最低/最高距离 | 近档 <32 / 中 32-96 / 远 >96；远档只留大轮廓 |
| despawn 方式 | 到期或玩家离开 64 格且无旁观者 → 客户端淡出；无 AI 实体 |
| 玩家转身后是否继续 | 继续（世界空间，不跟随视角）；直到 duration 结束或离开区域 |
| chunk 关系 | 不依赖实体的 chunk 加载；用 `LevelRenderer`/世界空间 VFX，锚定坐标 |
| server 是否创建实体 | **否**（纯客户端视觉）；服务器只发「区域+seed+duration」 |
| client renderer 类型 | `DistantVisualEntity`（客户端-only）或 `WorldRenderer` 钩子（[PROPOSED]） |
| packet payload | `ScenicEventSync`（[PROPOSED]）：`{scenicId, dim, anchorPos, seed, duration, startTick}` |
| seed | 服务器生成，客户端同 seed 渲染一致 |
| reconnect | 客户端重连读当前 `startTick/duration`，从正确进度续播 |
| dimension change cleanup | 离开维度即清本地 VFX，回原维度按当前进度续播 |

- 音效按距离衰减；Sky/Fog 离开区域、切维度、断线后恢复。
- 粒子预算见 10.1 表；不允许一个奇观生成几百个服务器实体。

| 8 | Server restart | 读 SavedData 恢复；INTRO 中途重启→续播或安全跳 COMBAT（不永久无敌） |
| 9 | Chunk unload/reload | Boss 卸载即停 Sequence 并存 state；重载续 CLEANUP/COMBAT |
