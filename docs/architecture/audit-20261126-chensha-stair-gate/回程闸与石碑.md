**石碑触发。** 玩家主手持镐对任一可达无字碑按攻击键或使用键。首次触发把独立的碑 ID 和共用 `return_lift` 写入同一结构实例的 `imperial_vault` 房间状态。单块碑的 `OPEN` 随独立 ID 更新，使它的碰撞消失。共用状态允许操作 (41,1,8) 的吊篮，乘员目的地为 (41,73,8)。吊篮井西壁下口外 (39,1–3,8) 的石英封堵仍适用，因此成功触发只证明状态解锁，井口实际可达性须单验。东北第四块碑 (43,1,9) 位于井内侧，未列入三条走法。[石碑和吊篮处理](../../../src/main/java/com/dynasty/dungeon/DungeonMechanismBlockEntity.java#L61-L86) · [共享状态和落点检查](../../../src/main/java/com/dynasty/dungeon/DungeonMechanismBlockEntity.java#L136-L152) · [井口记录](../audit-20261126-chensha-lift/shaft-shell-readback.json)

**阶梯闸条件。** `mercury_exit` 读同一实例下独立的 `mercury` 房间。正常进度由玩家投射物分别命中 (25,28,57)、(31,28,57)、(37,28,57) 三只兽眼，记入位 3、4、5，合计掩码 56。第三个不同目标使房间完成。核心累计 12 个有效开门 tick 并向已加载门体同步后，门的 `OPEN` 才解除碰撞。核心每两游戏 tick 更新一次，计时受区块加载、附近玩家与 tick 间隔约束。计时超时只释放 `trial_entry` 系列入口，并保留已命中的眼位。走到梯顶与破碑均不会写入兽眼或开闸进度。[独立房间状态](../../../src/main/java/com/dynasty/dungeon/DungeonStateStore.java#L10-L22) · [兽眼、目标和同步](../../../src/main/java/com/dynasty/dungeon/DungeonMechanismBlockEntity.java#L154-L157) · [进度与开闸逻辑](../../../src/main/java/com/dynasty/dungeon/DungeonRoomController.java#L34-L83)

**可引用的任务书表述**

> 从下层任一可达无字碑旁贴白石龙台低边，经南侧干桥走回中层石阶。梯顶的水银房出口闸由中层三只兽眼控制，闸闭时沿原路下阶。主手持镐击破无字碑会解锁另一条回程路线的吊篮。

仍需在同一座自然生成地宫中核对石碑交互回执、吊篮井口通行与落点、三条路线的实际碰撞和可见度，以及水银房已保存状态、第三只眼到门体更新的时序。源码允许已打开的门块在关闭时因活体占位暂缓恢复碰撞，因此重置后实机验收要确认门平面无人。[交互和碰撞](../../../src/main/java/com/dynasty/dungeon/DungeonMechanismBlock.java#L43-L70) · [门块同步与防夹](../../../src/main/java/com/dynasty/dungeon/DungeonMechanismBlockEntity.java#L181-L209)
