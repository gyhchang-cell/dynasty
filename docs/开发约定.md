# 开发约定（以后都按这个来）

> 这份文件记录本项目「改东西的方式」，避免重复踩坑。改任何东西之前先读一遍。

## 0. 总原则：先定位真因，再动手

* 出问题先去**看证据**：崩溃日志、`build/` 产物、`~/Public/.hmcl/logs/`、实例里的实际文件。
* 我们改的模组是第三方模组时，**直接反编译它的 class 看实现**（例如
  `javap -p -c -classpath modpack/mods/xxx.jar 全限定类名`），不要靠猜。
  例子：FTB Quests 的 id 是 `Long.parseLong(id, 16)`（有符号）就是从字节码里查出来的。
* 结论要落到「可复现的证据」上，再改代码。

## 1. 任务书（FTB Quests）改动规范

* 任务数据**只改生成器** `tools/art/gen_ftbquests.py`，不要手改 `modpack/config/ftbquests/**/*.snbt`
  （手改会在下次生成时被覆盖）。
* **id 必须能被有符号解析**：`Long.parseLong(id, 16)` → 数值必须 < `0x8000000000000000`，
  也就是首字符只能是 `0-7`。当前约定：
  `1` + 15 位 = 任务；`2` + 15 位 = 任务目标；`3` + 13 位 + 2 位 = 奖励；`4` + 15 位 = 章节。
* **每章结构**：1 个章首任务 + 2~4 条**并行支线**（支线长度故意不一样，用 `LANE_PATTERNS` 花纹轮转），
  章与章相连（章首 ← 上一章末尾）。不要写成一整条长链，也不要排成方阵。
* **每章都要归组**：章节必须挂到 `CHAPTER_GROUPS` 里的某一组（写进 `chapter_groups.snbt`），
  左侧栏才会出现可折叠的分组标题（「愚者 / 登神者」都是这么排的）。新章忘了归组，自检会报错。
* **每章都要副标题**：`CHAPTERS` 元组最后一格就是章节副标题（标题下面那行小字），别留空。
* **节点形状按重要性分配**（生成器已实现，别手改）：章首 `gear` 2.0 / 支线起点 `diamond` 1.5 /
  章末 `hexagon` 2.0 / 其余用全局默认 `circle`；坐标间距 x、y 都按 2.0 走。
* **`data.snbt` 的键名只能从 FTB 真实字段里选**（`version`、`default_reward_team`、
  `default_consume_items`、`default_quest_shape`…）。写错键 FTB 会**静默忽略**，
  界面看起来「配置没生效」但其实文件本身没报错 —— 自检脚本会拦住这类键名。
* **前置图必须无环（硬性）**：FTB 的 `Quest.isVisible` 会顺着前置递归，
  有环 = **一打开任务书就 StackOverflow 崩溃**。
  生成器是「先算全部前置 → 全局 DFS 只删回边」；自检里有真正的环检测。
  改动依赖时**先跑一次自检**，别直接导出。跨章的配方前置是允许的（会保留），
  但绝对不能让 A→B→A 出现。
* **章节内顺序**：`order_steps()` 会按配方做一次拓扑排序（材料在前），不要手工打乱。
* **一章 = 若干条「线」**：一条线 = 一个分类或一条支线，线首用 `branch=True` 标记。
  线首默认挂在章入口（互不干扰），带 `extra=[...]` 的线首挂到指定任务上；
  线内独立排序，所以「材料 → 成品」的排序永远不会把两条线搅在一起。
  **新加内容时不要把所有任务写成一长串** —— 一条线超过 10 个就该拆。
* **排布参数**：`STEP_X / STEP_Y = 1.5`、`CHAIN_GAP = 1.0`，并且整章最后**以 y=0 居中**。
  改这三个值前先想清楚：玩家反馈过「离得太远」「全堆在下面」两类问题。
* **前置只留必要的**：配方材料（①）、章节入口（② 只给本章第一条）、
  手写剧情门槛（④ `extra`）三类。**不要**再加「接上一条」这种自动兜底 ——
  玩家要能挑着做任务。想真的加一条锁，就用 `extra=[...]` 明确写出来。
* **排布与前置解耦**：`layout_lines()` 只按「branch 线」排（一条线一行、横着、y=0 居中）。
  排布不再看依赖图，所以放宽/收紧锁定都不会把版面弄乱。
* **兜底规则**：一个任务如果**本章内没有任何前置**，会自动接本章上一条
  （否则它会变成孤立的「根」，整章塌成一竖列 —— 饰品图鉴踩过）。
  所以内容里的顺序就是「线的顺序」，写的时候按逻辑顺序排。
* **装备 / 图鉴章要排在前面**（第一章、第二章之后），入口依赖用 `"c1"`：
  这样它们才能收全所有兵器 / 甲胄 / 饰品（去重规则是「同一物品只留第一次出现」），
  而且 `"c1"` 不参与主线递进，主线照样按 `"prev"` 往下接。
* **排布自检**：`verify_ftbquests.py` 会查「一竖列 / 一行 / 行距 > 4.5 格 / 跨度 > 40 格」，
* **每章都要铺开坐标**：布局用 `layout_tree()`；注意「章首任务的前置在上一章」这种情况，
  根节点判定必须是「前置都在本章之外」，否则整章坐标会全挤到 `(0,0)`（会表现为「一章只看得到一个任务」）。
* 任务说明写清玩法（升级链要写「配方需要先做出上一级的 XX」）。
* 奖励 = 物品 + 经验 + 少量功名；物品任务不收走物品（`default_consume_items: false`）。

## 2. 改完必须自检（导出流程已内置）

```bash
python3 tools/art/verify_ftbquests.py     # 任务书：id 可解析 / 前置能连上 / 引用存在 / 坐标铺开
python3 tools/art/verify_modpack.py modpack/mods   # 模组解析：缺前置、NOT-COMPATIBLE、JarJar 内嵌
./gradlew exportModpack                   # 上面两个自检 + 构建 + 生成三份整合包 + 同步四处目录
```

自检脚本的判定标准只准收紧、不准放松；发现新坑就往脚本里加一条检查。

## 3. 模组本体（Java）改动规范

* 新玩法尽量走**数据文件 + 生成器**（`tools/art/*.py`），少写一次性代码；生成器要可重复运行。
* 新增物品/方块/实体/维度/成就，必须同时补齐：注册 → 模型 → 贴图 → 语言（中英）→ 配方 → 数据（掉落/结构）。
* 涉及第三方模组（Curios / FTB）时**用反射桥接**（`DynastyCuriosSetup`、`DynastyFtbSetup`），
  不直接硬依赖，缺了也不崩。
* 语言文件由生成器写（`gen_dynasty3_json.py` 里的字典），改名字改那里。

## 4. 数值与体验约定

* 官阶 20 阶，功名门槛递增；官阶给属性与**饰品槽**（开局 3 格「王朝饰品」，每 4 阶 +1，最多 8 格）。
* 新增盔甲：先在 `gen_armor2.py` 的 `SETS` 表加一行 → 再在 `DynastyArmorMaterials`（材质）、
  `DynastyGear.EXTRA_SET_TABLE`（注册）、`DynastyBalance.SET_BONUS`（套装加成）、
  `DynastyTooltips.setName`（提示名）四处同步；名字必须一致，`verify_ftbquests` 会拦物品缺失。
  每件减伤别超过 0.35（四件封顶 92%）。
* 新增饰品：在 `gen_trinkets2.py` 的表格加一行 → `DynastyTrinkets` 里注册 + 加进 `IDS` 与
  `accessoryItems()` + 在 `apply()` 的 switch 里写效果（属性用 `addAttr`/`multiplyAttr`，
  周期性效果用 `tick()`）。
* 功名来源：打怪（Boss 大头，杂兵有 10 分钟上限）、与 NPC 交互、第一次获得新物品；**任务只给一点**。
* 饰品效果要**有战斗/功能意义**，不要出现只影响钓鱼/宝箱的「幸运」这类没用手感。
* Boss 大招必须**提前 1 秒预警**（`DynastyBossAI.telegraph`），并给反风筝手段。

## 5. 每次改完的收尾清单

0. 构建如果「卡住十几分钟没输出」，先看 `jstack <daemon pid>` 是不是卡在
   `EnvironmentChecks.testServerConnection`（ForgeGradle 的联网检查）。
   `gradle.properties` 里已经用 `systemProp.net.minecraftforge.gradle.check.certs=false` 关掉了它。
1. `./gradlew exportModpack`（构建 + 双自检 + 打包 + 同步）
2. 复核实例：`~/Public/.minecraft/versions/Dynasty 王朝/` 下的 `mods/` 与
   `config/ftbquests/quests/chapters/`（任务条数、章节数、坐标）
3. 更新文档：`docs/更新日志-1.4.0.md` 追加一轮（写清「原因 → 修复 → 证据」），
   `modpack/README.md` 里对外描述同步
4. 回复时给用户**可验证的证据**（命令输出、坐标抽查、条数统计），并把「需要实机确认的点」标出来

## 6. 第三十二轮之后新增的四条流水线（照这个做，别手改产物）

* **新材料**（`tools/art/gen_relic_materials.py`）：一个自包含脚本搞定
  贴图（artlib 画）→ 模型 → 配方 → 中英词条 → 打印 Java 注册行；
  配方只用**已有材料 + 图纸**，不新增材料物品（和既有高阶材料一致）。
* **饰品（每批一个生成器）**：`gen_trinkets3.py` / `gen_trinkets4.py` ……
  `verify_gear.py` 会把所有 `gen_trinkets*.py` 的表**并起来**核对
  「生成器表 ↔ `DynastyTrinkets.EXTRA_TABLE` ↔ Curios 标签 ↔ 贴图 / 模型 / 配方 / 词条」，
  所以加一批就要保证四处同名一致（EXTRA_TABLE 的行直接由生成器打印出来粘过去）。
* **结构（真正的 worldgen 结构）**：
  `structure/XxxStructure.java`（`findGenerationPoint`，用 `WORLD_SURFACE_WG` +
  `minBuildHeight + 5` 守卫，虚空里不生成）+ `XxxPiece.java`（继承 `DynastyStructurePiece`，
  用 `set/fill/walls/createChest`）+ 在 `DynastyStructures` 注册类型与部件类型
  （部件反序列化器放独立的嵌套类，避免静态初始化自引用）+ `gen_new_structures.py` 写
  `structure/` 与 `structure_set/` 两份 JSON。改完**必跑** `verify_worldgen` 与 `verify_feature_order`。
  结构没法做任务条目（任务条件只有物品 / 击杀 / 成就），要提就写进任务描述或让玩家 `/locate`。
* **科举题库**：题目只改 `src/main/resources/data/dynasty/keju/questions.json`
  （`tiers[]` → `questions[]`，每题固定 3 个选项、`correct` 为 1..3、档位 `minMerit` 升序，
  每档 ≥ 10 题），改完跑 `python3 tools/art/verify_keju.py`（已接进 `exportModpack`）。
  Java 里的内置兜底题库只在文件缺失时用，**不要**拿它当题目来源。
* **坑（务必记住）**：`verify_ftbquests.py` 的「物品是否存在」是**从构建出的 jar 里读的**
  （`build/libs/dynasty-*.jar`）。新增物品后如果不先 `./gradlew jar`（或直接 `exportModpack`）
  就跑去跑自检，会误报一堆「物品 xxx 不存在」。
* 食物类内容按 `gen_ftbquests.py` 的 `DROP_TARGETS` 规则**不进任务书**（「吃食只留饺子 / 茶 / 美酒三样」），
  加食物时别去任务书里塞条目。
