# 遗迹机关与解谜宝室 v1（ruin-puzzles-v1）

独立探索玩法：一个共享的机关控制器 + 三种机关 + 三个可玩宝室模板。
MC 1.20.1 / Forge 47.4.10。开工前已确认仓库**没有**既有机关/解谜系统（全库 grep `机关/puzzle/星盘/编钟/四象` 无命中），
因此按独立系统实现，未改动 Boss、主线任务、悬赏、官阶、饰品槽、毕业装备与战斗特效。

## 1. 怎么玩（三种机关）

| 机关 | 部件 | 操作 | 完成条件 |
| --- | --- | --- | --- |
| **星盘归位** | 4 个星盘（`star_dial`，四朝向各有独立方块状态与旋转模型） | 右键星盘旋转 90° | 4 个都转到线索所指方向 |
| **编钟回声** | 5 个编钟（`echo_bell`，音位按房间内排序 1–5） | 右键**控制器**听演示 → 按顺序右键编钟 | 输入序列与目标一致（长度 3 / 4 / 5） |
| **四象点灯** | 4 盏灯（`element_lamp`，青龙/白虎/朱雀/玄武四种贴图） | 右键任意灯 | 点一盏会切换**自己 + 顺时针相邻**一盏；四盏全亮 |

* **线索石板**（`clue_tablet`）放在每个部件**正上方**：星盘室逐块给出「第 N 座星盘应朝向 X」，
  编钟室/灯室给出规则说明；**可以反复右键读**，不需要退出游戏查攻略。
* 提示走动作栏/聊天（翻译键，中英齐全）：尚未开始、演示中、输入错误（会清空本遍输入并说明）、
  机关完成（石门开启）、已领取、背包不足（奖励保留）。不会持续刷屏。
* **重置**：对着**控制器潜行右键**。已解开或已领奖的房间**拒绝重置**（防止用重置刷奖励）。
* 音效：原版 `NOTE_BLOCK_BELL` 按 5 个音高区分，并同时用文字显示音位（**关掉声音也能完成**）；
  音效与提示只发给控制器 12 格内的玩家，不广播全服。
* 演示期间**不接受输入**；重复点控制器**不会叠加**多个播放流程（已有演示在跑时直接提示"演示中"）。

## 2. 放置模板（仅管理员，白名单）

```
/dynasty_puzzle list                      # 列出三个模板 ID
/dynasty_puzzle place <star_room|bell_room|lamp_room> [0..2]
```

* 需要**权限等级 2**；房间建在**准星指着的方块上方**（控制器就在该位置）。
* 只接受上面三个白名单 ID，**不接受任意结构路径**，也**不接受任何奖励参数**（奖励永远来自模组自带战利品表）。
* 参数 `[0..2]` 选择该机关的三套布局之一（写进控制器方块状态，重载后不变）。
* 每个模板包含：入口（z=+4 开口）、主室、机关部件、部件正上方的线索石板、封印石门（z=-4）、
  门后的宝室与奖励台（祭坛）。尺寸 9×5×11 以内，全部复用已有方块
  （宫廷砖 / 汉白玉 / 玉块 / 宫灯 / 祭坛）。

**是否已自然生成：没有。** 项目现有遗迹是 Java 结构生成器（`com.dynasty.structure.*`）+ 少量 NBT 模板，
没有可靠的"模板池扩展点"，按需求"若必须大改生成器则不强行接入"，本轮只交付**可放置模板**，
未接入任何遗迹的生成池，也**没有**改 `worldgen` / `structure` / `structure_set`。

## 3. 房间身份、存档与权威

* 房间身份 = **维度 + 控制器坐标**（`PuzzleRules.roomKey`）。同一模板多次放置天然是不同房间；
  同一房间换人交互也是同一个状态；**不沿用模板里写死的身份**。
* 部件用**相对控制器的偏移**做键落盘（可验证的相对坐标）：区块卸载/重启后朝向、灯阵、已解开、已领奖都保留；
  某个部件被拆也不会让其它部件错位。
* 机关类型与布局取自**控制器方块状态**；房间归属由服务端在部件周围**有限范围**（±12/±8）内找最近控制器得出。
  客户端只说"我右键了这个方块"，**坐标、答案、完成状态、奖励一律服务端计算**。
* 交互校验：距离 ≤ 6 格、方块身份必须是本机关的部件、房间状态合法。
* 控制器可操作范围有限：只在自己的 ±12/±8 盒子里发现部件、只移除自己范围内的封印石。
* 编钟演示进度**不跨存档保存**：重启/重载后自然回到"等待演示"（需求允许，不要求跨重启继续计时）。

## 4. 奖励与防重复

* 独立战利品表 `dynasty:puzzles/ruin_reward`：绿宝石 2–4 / 铁锭 1–3 / 面包或火把或箭（三选一）/
  少量 `dynasty:jade` 或 `dynasty:cinnabar`。**没有** Boss 信物、毕业装备、永久属性、饰品槽。
* **公共奖励只发一次**：解开时按房间身份播种抽一次，结果**编码存进房间状态**；
  之后任何人领奖都发同一份，**背包满重试不会重新抽奖**。
* 两名玩家同时点：服务端串行处理 + 状态里只有一次可领 → 只有第一个成功，另一个收到"已被领走"。
* 背包空间不足（按奖励叠数算）：**拒绝领取并保留可领取状态**，不把物品丢地上。
* 失败边界：先扣/先发的只有"状态写盘 + 物品入包"这两步，同 tick 内先判定后发放，
  **不声称绝对崩溃事务安全**（极端崩溃下可能少发一次，但不会重复发）。
* 封印石门解开时**只移除本房间范围内的封印石**，不动其它方块；玩家可以自己挖墙绕过去，
  但**绕过门不等于完成机关**，奖励只认控制器的真实完成状态。
* 控制器**不提供物品**（没有生存配方、也没有创造物品），只能用管理员命令放置；
  部件方块有物品但单独放不能形成可领奖房间（必须有控制器）。不会掉落带完成状态的控制器物品。

## 6. 实际测试结果

```bash
$ ./gradlew compileJava --offline          # BUILD SUCCESSFUL（error 计数 0）
$ javac -cp build/classes/java/main -d /tmp/puzzle_test tools/puzzle/PuzzleRulesTest.java
$ java  -cp build/classes/java/main:/tmp/puzzle_test PuzzleRulesTest
通过 44 项，失败 0 项
✅ 遗迹机关核心逻辑测试全部通过

$ python3 tools/maintenance/check_all.py   # 资源/词条/配方自检（上一批工具）
检查文件 966 个 · 确认错误 0 · 警告 0 · 跳过 0
```

测试覆盖（`tools/puzzle/PuzzleRulesTest.java`，全部是实际断言）：
星盘每次旋转与**四次回到原朝向** · 三套线索与目标一一对应（错一盘即不完成） · 编钟正确/错误序列与长度不足 ·
**演示中不接受输入 / 重复演示请求不叠加**（`bellAcceptsInput` / `demoMayStart`） · 灯阵切换规则 ·
**环序为俯视顺时针**（北→东→南→西） · 三套灯阵 BFS 求解**可解且非开局即完成** ·
重置不刷新已解/已领房间 · 两房间状态隔离 · 同模板两次放置身份不同、跨维度不串 ·
行格式**存档往返**（灯阵/已解开/奖励结果/已领奖） · **关键部件缺失不完成** ·
两人同时领取只有一个成功 · 背包不足重试不重新抽奖 · 重复数据包不重复发奖 ·
**专用服务器不引用客户端类**（机关包与命令里没有 `net.minecraft.client` / `Dist.CLIENT`）。

## 7. 未实测项与限制

* **界面与模型没有在游戏里看过**：星盘的旋转模型、灯的四种符号贴图、控制器的观感都只是资源层校验通过，
  没有启动客户端确认（无 GUI，提示走动作栏/聊天，所以没有新增界面类）。
* **音效只在代码层区分音高**，没有实机听过；"关掉声音也能完成"依据的是同时发送的文字提示。
* **没有跑真实服务器/独立测试存档**：持久化只做了单元级的行格式往返测试；区块卸载、重启、
  多人并发点击都没有实机验证。
* **没有自然生成**：只能用管理员命令放置；未接入遗迹生成池（原因见 §2）。
* 编钟演示是服务端 tick 调度（仅在有演示时遍历活动演示，不扫世界）；演示进度不跨重启。
* 灯阵的"顺时针"由相对坐标的俯视角度确定（`atan2(dz,dx)`），房间如果被整体旋转建造，
  部件之间的相邻关系仍按实际坐标计算，但线索石板的编号顺序以房间内排序下标为准（同模板放置时固定）。
* 星盘线索是"逐盘给出目标朝向"，答案唯一但偏直白；这是为了满足"必须能由线索唯一推导、不能纯猜"。
* 奖励的极端崩溃边界不做绝对事务承诺（见 §4）。
