# 建筑扩建 v2

## 本轮内容

- 国子监由 34×34 扩为 46×46，占地增加约 83%；声明高度由 14 调为 18。
- 保留旧存档中 34 格结构起点的旧生成分支，避免未生成区块混入大尺寸布局。
- 新布局有主讲堂、15 书架附魔区、带座椅的讲案、西侧藏书阅览室、制图桌、东侧工坊和炼药角。
- 工坊使用真实工作台、切石机、锻造台、熔炉、酿造台及水炼药锅。不是新的职业或自动生产系统。
- 双池庭院、两座平桥、横向有顶长廊、窗带、木梁、瓦檐、玉石脊线和门楼。只组合现有方块，未新增方块 ID 或贴图。
- 国子监仍为三个原等级战利品箱，没有因扩建翻倍增加宝物。
- 宫殿正门增加连续三级台阶、分层屋檐和双侧浅池。
- 主殿移除中轴密集柱列，清空内部地形，保留两侧柱列；增加案席、红毯、制图桌和末影箱。
- 主殿箱子不再覆盖鼓，香炉等移出中轴通路。

## 启动阻塞修复

实际启动独立测试服务器时发现既有机关功能的两个注册错误：
1. Part 在 Block 父构造函数调用状态定义时读取尚未赋值的 dial/lamp 字段，导致方向/灯属性缺失。改用专用子类声明属性。
2. 机关星盘物品与原有饰品共用 dynasty:star_dial，导致注册覆盖。机关方块 ID 保留，物品改为 dynasty:puzzle_star_dial；恢复原饰品的物品模型。

仅修复启动和命名冲突，没有改机关规则，也没有把尚未验收的机关直接接进自然建筑。

## 验证与限制

- 离线构建通过；世界生成引用、特征顺序、战利品表检查通过。
- 使用 build/architecture-gametest 独立世界运行 GameTest，未进入用户存档。
- 新布局测试直接捕获实际生成器的放置调用，验证边界、工作站、书架、三个箱子，以及入口到主殿/厢房/双桥的路径。
- 没有客户端视觉验收；不能把服务端测试等同于光影效果或山坡适配已实测。
- 现有已生成建筑不会自动升级。请在新生成区域寻找国子监与宫殿；不要删除旧区块来强制更新。
- 只更新项目，不运行会同步启动器的 exportModpack。

复验：`./gradlew --offline -I tools/art/architecture-qa.init.gradle runGameTestServer`。
应核对日志中的测试数量及通过结果，不能只看 Gradle 的 BUILD SUCCESSFUL：加载失败也可能返回成功状态。
