# Isolated native migration evidence probe

This directory contains a QA-only Clone observer and a separately opted-in historical-world reader for the current six-class private candidate. It does not replace the historical five-field `OldWorldQa`. Neither changes progression, grants items, kills, respawns or issues rewards. Main coordination owns preparation and runtime authorization.

The production source review is complete in `todo-evidence-review-20261101/legacy-migration-current-source-independent-review-20261102.json`; its count-only clarification says **seven** native archive entries. Source review does not certify native remapping or Clone dispatch.

The observer requires packed QA/current candidate jars, their actual loaded file hashes, the exact independently reviewed107-field fixture and contract, and pre-existing absolute private root/instance/output directories. The root must resolve under a `build/cod4-legacy-native-20261102` directory. Output and instance cannot contain one another. Server world must resolve to that instance's `saves/legacy-copy`. It never creates a world or changes a launcher/ready/execution marker.

All file names include a unique session or explicit case. Writes use `CREATE_NEW`; a case ID cannot silently replace historical evidence. Commands require operator permission, the actor's actual player source, exactly two live distinct non-FakePlayer server connections, and already-enabled private `keepInventory`. The observer does not enable that game rule.

`/legacyqa arm <unique-case> <peer-UUID> death|end` records both players' original persistent data, full player NBT, and complete native inventory including equipment/offhand. It then waits for a real `PlayerEvent.Clone` for the original actor object and expected death flag. A duplicate actor Clone, unplanned peer Clone, changed peer object, changed connected-player count, wrong world, or600-server-tick timeout produces failure evidence. Actual death/End travel and client input must be supplied independently.

At LOWEST the probe records the old/new raw data and compares the reviewed fields, exact types, valid UUID, valid economic pair, and root/nested first-kill aliases. It describes absent/malformed fields separately and **never** treats zero/partial coverage as107 fields. LOWEST does not certify all other same-priority/later listeners have completed. A further snapshot20server ticks later records actor/peer state and inventory comparisons. Differences remain visible; ordinary progression consumers may legitimately change state between arm/event/tick, so a coordinator must explain them rather than attribute every delta to the copier.

Every comparison and output fixes native/overall acceptance to false. `CAPTURED_NATIVE_CLONE_PENDING_ANALYSIS` is capture completion only. No output certifies C2S origin: actual native respawn input/packet evidence must be independently bound to case/player/session. End return needs its actual native travel evidence. Old-item remap requires a separate historical world-snapshot load, identity/count/NBT/ForgeCaps comparison and save/reopen. The historical inventory did not contain healing_talisman; its separately labeled artificial fixture cannot be called historical inventory coverage. FTB-unavailable fallback and unresolved/unknown negatives remain separate cases.
