- 历史失败日志保留在 `evidence/20261022-fixture-error/`、`evidence/20261022/` 和 `evidence/20261023-before-contract-correction/`；它们是已被纠正的测试错误，不能重新列作未修产品缺陷。
- `evidence/20261023/task-location-audit.json` 是**修复前历史快照**：当时有 186 条指向已不存在章节名的位置记录，引用的任务 ID 均存在。主代理随后只校准映射表的 `CURRENT_TASK`、`TASK_STAGE`、`NOTES`，保留 ID 及其他十列；其 `docs/cod4/audit-20261022/task-location-refresh.json` 记录了 252 行变更、317 处章节及 stage 引用校准，对应当前 1259 个节点。186 与 317 的统计口径不同，不能作为同一指标比较。2026-10-23 本次补注已核对当前表 SHA-256 为 `f50b848c39330ae92e0741338c7d910df18dee421b20c5af773aabf3453aced9`，与主代理修复后的哈希一致；旧快照中的表哈希只代表修复前版本，旧位置问题不再列作未修缺陷。本工具未改映射表；重跑审计使用带输入哈希的新文件名，保留旧快照。

## 重跑

所有构建输出、项目缓存、冻结源文件和测试世界均在自己的 `.work/` 中，测试源集不会进入发布 jar。不要与本工具正在进行的运行同时刷新快照。选择新的 `journeyRun` 名称，以免复用上次世界。

```sh
python3 tools/cod4/journey-acceptance/freeze.py
JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home ./gradlew \
  --offline --no-daemon --max-workers=2 \
  --project-cache-dir tools/cod4/journey-acceptance/.work/project-cache \
  -I tools/cod4/journey-acceptance/native.init.gradle \
  -PjourneyRun=server-repeat runGameTestServer \
  > tools/cod4/journey-acceptance/.work/native-repeat.log 2>&1
python3 tools/cod4/journey-acceptance/audit.py \
  --run server-repeat --log native-repeat.log
```

`audit.py` 只有在服务端确实完成、Gradle 成功且全部细分检查通过时才写最终报告。原始记录、完整日志、源文件哈希和逐配方输入/产物索引位于 `evidence/20261023/`。其他聊天造成的快照漂移单独记录，Java/数据漂移与资产漂移分别列出。
