Contract and safety:
- New optional inventory is constructed separately and appended atomically.
  Missing mappings disable only inventory; invalid observations omit it and retry
  after 50ms. Existing bridge fields and heartbeat/socket behavior remain usable.
  A 59000-character ASCII guard prevents inventory pushing a bridge packet beyond
  the existing 60000-byte datagram threshold.
- Main-thread check occurs before inventory/game-object reads. All sampling is in
  the existing scheduled callback. No game field writes or game input calls added.
- selected is 0..8; only nonempty slots, unique index 0..8, at most nine entries.
  Item IDs >0, metadata >=0, count 1..64. Damageable stacks must have max>0 and
  damage<=max; vanilla consumes a stack when damage>max, not at equality.
  Invalid nonempty candidates omit the entire inventory, rather than pretending
  the selected slot is empty. Null/zero/negative-count entries are empty.
- keys always has nine fresh configured LWJGL values. No default key guesses.
  Zero (unbound) and negative mouse mappings remain actual values; native-key
  support and key simulation stay with Swift.
- blockedKeys:[Int] contains current codes of ALL non-hotbar bindings in avh.ax.
  This combined keyBindings field was freshly verified with /usr/bin/javap:
  avh constructors build 24 action bindings at offsets 869..1059, add aw at
  1061..1064, and store the combined avb[] into ax at 1070. Options loading and
  saving iterate ax as well. No hard-coded action names/default codes are used.
  Exclude only binding objects identical (==) to one of the nine aw objects;
  an action with the same keycode as a hotbar binding remains in blockedKeys.
  Preserve all action codes, including duplicate codes, zero, and negative mouse
  codes; Swift decides native-key admissibility. Read both arrays and codes fresh
  each packet on the main thread. No key-cache or game field writes added.
  Strict ax field type/instance validation is part of optional mapping setup;
  absent/wrong mapping permanently disables inventory independently of the bridge.
  Null combined arrays/entries, duplicate hotbar objects, missing hotbar identities,
  or no non-hotbar action coverage omit the entire inventory, never an empty
  blockedKeys fallback. Action array order and count are not hard-coded.
- hitKind/target/blockID/hardness, selected, count, keys, blockedKeys and scores are fresh every
  packet. ENTITY/MISS/unknown have null block fields; no Entity.rayTrace fallback.
  The pre-existing top-level useHit logical ray remains unchanged for the bridge.
  bfk.a(float) initially writes a block ray to ave.s, then can replace it with
  entity hit at bytecode offset 569; this is why ave.s is authoritative.
- Score is relative to EMPTY HAND = 1, with no handScore field:
    S = stack.a(block)
    if S>1 and efficiency>0: S += efficiency*efficiency + 1
    handCan = block.material.l()
    candidateCan = handCan || stack.b(block)
    score = S * (handCan ? 30 : 100) / (candidateCan ? 30 : 100)
  Derivation: wn.a(afh) gates efficiency on base>1; wm.b(afh) permits hand-friendly
  material or candidate harvest; afh.a(wn,adm,cj) divides by hardness and /30 or
  /100. Hardness and common haste/fatigue/water/ground multipliers cancel in the
  ratio. E.g. stone, strength6, efficiency2, harvestable -> 11*100/30=36.6667;
  insufficient harvest tier with strength2 -> 2, not a harvest-capable score.
  Non-block, instant-break, and unbreakable targets receive neutral finite score1;
  hardness is sent unchanged so Swift can exclude tool swaps for those targets.
  Bed ID26 is sent unchanged; special sword preference remains entirely in Swift.
- identity is '<itemID>:<metadata>:sha256:<64 hex>' of the entire typed NBT tree.
  Compound keys sorted; list order and declared type preserved; native primitive
  payloads include lengths, numeric types, arrays and strings. Null and empty
  compound differ. Count is excluded, while a user NBT key named Count is included.
  Cache identity only, keyed by slot stack/item/tag object plus itemID/metadata,
  expired at >=50ms. In-place NBT changes are reread at expiry. World/player changes,
  empty slots, inactive samples and optional errors clear relevant caches.
  inventory.age seconds measures the oldest identity timestamp, including digest
  computation; fresh actual targeting is never cached. The 50ms cache is not a
  hard latency guarantee if the JVM itself pauses.
  NBT budget per observation: 65536 serialized bytes, 4096 nodes, depth<=64.
  Oversize/malformed/unknown NBT omits inventory; no partial or fallback digest.
- geometry is volatile, defaults true. Snapshot captures it once and emits that
