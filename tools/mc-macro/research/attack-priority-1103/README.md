## 原因与实现

1. 旧 `MeleeReadiness.problem` 和控制器 `tick` 同时以 `using || rightDown` 拒绝/暂停近战。它既包括真正的副手使用，也包括游戏观察到的右键按压，不能当成主手没有剑。新增测试在旧版复现 27 项中的 18 项失败，记录 `/Users/a15356015027/Desktop/dynasty/tools/mc-macro/.build/candidates/attack-priority-1103/before.log`。
2. 本地 26.1 Minecraft 字节码表明，处理使用物品的分支会消耗攻击点击；直接删检查并点击并不可靠。新逻辑用已有 macOS 原生事件路径发送 **右键松开**，等待后续游戏刻的新鲜状态明确结束使用，再进入原攻击逻辑。不新增调用游戏动作 API，不修改 Java 读数组件。
3. `SwordRightInput` 在开关、正确主手、有效前台及观察条件下拦截右键按下，右拖拽转为鼠标移动保留瞄准，配对消费其松开。关闭/换物品后的新右键按压正常透传。若中途丢失松开，新原生按下也不会永久被吞。
4. 为避免伪造成功，最多尝试三次松开，间隔至少 0.1 秒且需要更新的读数；0.6 秒仍未确认则关闭剑斗并明确提示“右键释放未生效”，不无限等待、不盲打。自定义物品使用键不是右键时不猜键位。
5. 原普通按住左键连点依旧尊重右键/物品使用，不与剑斗的主动接管混用。主手食物、方块、锚或工具不触发接管。原剑/斧/空手范围保留。
6. 自动出手仍要求真实前台、活动游戏、准星有效且可触及目标、适当恢复状态。距离、目标护盾、无效输入、菜单、世界变化、过期读数与失焦保护均未删除。不是开启后无目标无限空挥。

**行为影响：持剑/斧/空手开启剑斗时，右键举盾或副手使用会被结束，新的右键使用会被剑斗优先策略拦截。要手动举盾，关闭剑斗；要吃主手食物，切到食物后重新按右键。** 这不是自动盾斧防御策略，也不承诺提高所有对战的胜率。
